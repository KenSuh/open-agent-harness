# P7t Toolkit with Provenance and Automatic Skill Updates — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A beginner gets a maintained toolkit. The kit ships the redistributable skills unchanged with
their provenance, installs them (or a linked item's official installer) on request, ships MCP launch
templates with placeholders only, and keeps installed skills current from an allowlist of upstreams,
with license, load and privacy checks, lease-aware deferral and rollback.

**Architecture:**
- **The allowlist** (A15) ships as package data: `src/oah/templates/toolkit/upstreams.json`. It names
  every bundled item (repository, subpath, tracked ref, expected SPDX id, license path, the skill
  folders to install) and every linked item (source, version, license, official install steps).
- **Bundled copies** live in `skills/<item>/`: the upstream subpath's files byte for byte, the upstream
  license (and NOTICE) file, and `UPSTREAM.json`. The pin is the `commit` in `UPSTREAM.json`.
- **Installed copies** are skill folders under `.claude/skills/` or `.agents/skills/` (project), or
  `~/.claude/skills/` or `~/.agents/skills/` (user, with consent). Each carries the license files and a
  `.oah-skill.json` marker that is its pin. `read_skill` reads the marker, so selection (P3b) always
  sees the installed version.
- **Updates** fetch the tracked ref into a temporary folder with `git` (public, no credentials), stage
  the new item, run the checks, and only then swap each destination with a backup; a failed check
  leaves the last good pin in place, and a failed swap restores the backup.
- **Where updates write (owner decision, coordinator note 2):**
  - automatic updates write only a **kit cache** in `<state>/toolkit/cache/`, outside the working tree;
  - tracked project copies (`.claude/skills/`, `.agents/skills/`) are pins and change only through
    `oah skills update --project`, which takes its own lease (`oah-skills`) on those folders;
  - user folders change only through `--global` with confirmation, never on a schedule;
  - selection precedence (`oah.toolkit.locate.locate_skill`): project copy, kit cache, user, plugin;
  - unlazy is never updated by A15; `[skills] pins = [...]` holds items.
- **Scheduling:** a due check (default every 1 day) runs from mutating `oah skills` commands when no
  lease is active. Preparation runs unlocked; publication holds the state lock (`<state>/.lock`) from a
  fresh idle check through the swap and the run record, so no lease can start mid-update. An optional
  launchd / Task Scheduler entry runs `oah skills update --scheduled` with consent.
- **C4 publication rule:** installs and updates at every level share destination locks when reading
  the preparation identity and from the publication identity comparison through replacement. Resolve
  only the parent, create it and lstat it as a real directory; never resolve the destination itself.
  Keep `.oah-publish-<digest>.lock` in that parent, with a digest of only the normalized, case-folded
  destination name. All clients and mount aliases then open the same shared lock file regardless of
  device/inode IDs, including while a linked destination is renamed away. On case-sensitive volumes
  folding may conservatively serialize distinct names. A changed destination refuses installation or
  defers updating; rerun the command against the current copy.
- **C2 fetch/staging safety rules:**
  Fetch processes receive only PATH, locale, required Windows system variables, temporary homes and
  credential-free proxy settings; user information in a proxy URL is refused with retry guidance.
  Staging rejects all Windows device names (including console devices, COM0–9 and LPT0–9, extensions
  and spaces before extensions) before writing. Required metadata uses YAML 1.2 core scalar types;
  quote values that should remain strings.
- **Coordinator follow-up after P7t lands (C1 finding 7):** ordinary mutating command owners, including
  `oah start`, must call `oah.skills_cli.before_mutation(info, state)` before acquiring the next task's
  lease. This lane exposes and tests that best-effort function; it does not modify other command owners.
  Call it only on write paths, never on read-only, `--check` or `--dry-run` paths. It respects opt-out,
  interval and active leases, writes only the kit cache, and reports maintenance errors without failing
  the caller. Until that follow-up lands, use mutating skills commands or the optional OS scheduler.

**Tech Stack:** Python 3.11+ stdlib (`json`, `hashlib`, `plistlib`, `xml.etree`, `unittest`), `git`
through `oah.engines.proc` and `oah.paths`, optional `gitleaks`.

**Spec:** `docs/PLAN.md` 3, 5.2, 5.3, 5.11, 8, 9 and amendment 3 (A9, A13, A15, A17), carried in the
lane intent `p7t` r1.

## Global Constraints

- Everything from the P1 and P2 plans still applies: stdlib only, never `shell=True`, UTF-8 on every
  read and write, parsers accept CRLF, a Korean one-line header on new `.py` files, tests write only
  inside temp folders, Windows-only behaviour gets a `skipUnless(os.name == "nt")` test plus a portable
  test of the same rule.
- **No keys (A17).** Fetches never pass a token: git runs with `GIT_TERMINAL_PROMPT=0`, an empty
  `credential.helper` and `core.askPass`, isolated system/global/XDG configuration and credential homes,
  disabled hooks/templates, and no checkout or filters. Required files come directly from Git blobs.
  Repositories must be `https://` URLs without user info,
  query or fragment (tests use local fixture paths). Templates hold `${NAME}` placeholders (Claude) or
  `env_vars` names (Codex) only. Tests build fake keys and home paths from fragments at runtime.
- **Vendored files are never edited.** If any file of an item fails the repository privacy scan
  unchanged, the item is link-only. No allowlist entry is added.
- **Global files need consent.** Anything outside the project (user skill folders, the launchd plist,
  the scheduled task, a linked installer) is shown first and needs `--yes` or an interactive `y`.
  Without a terminal and without `--yes` the command refuses with `OAH_SKILLS_CONSENT_REQUIRED`.
- **Read-only commands write nothing.** `oah skills list` and `oah skills update --check` create no
  file in the project or the state folder (the check fetches into a temporary folder that is removed).
- **Exit codes:** 0 ok, 1 refused (consent, conflict, failed update, leases active), 2 usage,
  69 environment (git missing, network or fetch failure, corrupt catalog or state).
- **Config:** `[skills]` with `DEFAULTS = {"update_interval_days": 1, "auto_update": True,
  "size_jump_ratio": 2.0, "size_jump_min_bytes": 262144, "pins": []}`. Core functions take settings as
  parameters; only `skills_cli.py` calls `oah.config.load_config(root).section("skills", DEFAULTS)`.
- **Update log:** every non-`current` result is appended to `<state>/toolkit/updates.jsonl` with old
  and new commits, the diff summary, the time and why (`automatic`, `update`, `update --project`, ...).

## Decisions taken in this lane

- **Vendor set.** Of the 14 `vendor` rows, 11 are skills or plugins and 3 are MCP servers. The MCP
  rows become the `mcp/` templates (an npm-launched server is not a skill folder). Of the 11:
  - vendored (8): `computer-use`, `orca-cli`, `orchestration`, `typesafe-ai`, `skill-creator`,
    `mattpocock-skills`, `codex-plugin-cc`, `ponytail`;
  - link-only by the privacy rule (2): `unlazy` (a test file holds an absolute home path) and
    `superpowers` (a script assigns a `TOKEN` variable, another holds a home path);
  - link-only because upstream has no skill folder (1): `graphify` (its CLI generates the skill from a
    template file; vendoring would mean renaming files).
- **Plugin items vendor their skill folders.** `mattpocock-skills`, `ponytail`: subpath `skills`, plus
  the repository LICENSE. `codex-plugin-cc`: subpath `plugins/codex` (its skills refer to the plugin's
  scripts). Plugin hooks and commands still come from the official plugin install, which `oah skills
  list` shows next to the bundled copy.
- **`mattpocock-skills` installs the 27 skills its plugin manifest lists**; the deprecated and
  in-progress folders are vendored unchanged but not installed.
- **Codex skill folders** are `.agents/skills` (project) and `~/.agents/skills` (user), per Codex's
  skill-root resolution; `~/.codex/skills` is its deprecated location.
- **Where install copies from.** The kit cache first, then `skills/` beside the source tree (a clone or
  editable install, or `OAH_KIT_DIR`). A wheel install has no `skills/`, so with no cache entry install
  fetches the item at the catalog's pinned commit (`bundled[].commit`, equal to `UPSTREAM.json`) and
  re-checks its license before copying.
- **unlazy** is linked, not vendored: its repository fails the privacy scan unchanged, and A13/A15 say
  it installs only at lane P5's contract-tested pin. Its catalog step points at that pinned install;
  until P5 lands, there is no runnable unlazy step here.
- **humanize-korean** (coordinator note 4) is an opt-in A13 item: vendored from the public upstream at
  `b37e0206…` (main at check), `default = false`, `select_for = ["korean-prose"]`. `include` vendors only
  its runtime folders (`skills`, `scripts`, `agents`, `.claude-plugin`, LICENSE), and `support` copies
  `scripts/` into the installed skill, as upstream's own copy install does. `--all` skips opt-in items.
- **CLIs** from the inventory are in the catalog's `clis` list (`install_macos` from the inventory), so
  `oah doctor` (lane P8) can read the same catalog.

## Review Focus

- No path through `fetch`, `install`, `update` or `schedule` passes a credential or runs a shell.
- Checks fail closed: an unreadable license, an unknown SPDX id, a parse error or a gitleaks error is
  a failed update, never a pass.
- Rollback: after any failure the destination is byte-identical to the last good pin.
- Shared publication holds the state lock through the fresh idle/due and preparation-input identity
  checks, swaps and run record. Project and kit-maintainer writes take their own scoped lease;
  `--vendored` requires the current kit checkout, consent and a lease covering `skills/` and the catalog.
- `skills/` content equals upstream blobs (`git ls-files -s` blob ids equal `UPSTREAM.json` `files`).

## Tasks

### Task 1: Skill metadata — `src/oah/toolkit/skillmeta.py`

- `parse_frontmatter(text: str) -> dict` — the YAML subset skills use: `key: value`, single and double
  quoted scalars, `|`/`>` block scalars (with `-`/`+`), nested maps and `- item` lists; CRLF accepted;
  raises `SkillError("OAH_SKILL_INVALID", ...)` on anything else.
- `@dataclass(frozen=True) SkillInfo(name, description, version, source, license, path)`.
- `read_skill(path) -> SkillInfo` — `path` is a skill folder or its `SKILL.md`. Version, source and
  license come from `.oah-skill.json` (installed), else the item's `UPSTREAM.json` (bundled), else the
  frontmatter (`version`, `license`, `metadata.version`).
- `load_problems(skill_dir) -> list[str]` — frontmatter parses, `name` and `description` are non-empty
  strings, and every relative Markdown link target outside code spans and fenced blocks exists inside
  the item.
- Tests (`tests/test_toolkit.py`): `test_frontmatter_block_scalars_and_crlf`,
  `test_frontmatter_rejects_broken_yaml`, `test_read_skill_prefers_marker_then_upstream`,
  `test_load_problems_missing_name_and_missing_reference`, `test_load_problems_ignores_code_links`.

### Task 2: Allowlist and provenance — `src/oah/toolkit/catalog.py`, `src/oah/templates/toolkit/upstreams.json`

- `load_catalog(path: Path | None = None) -> Catalog` with `Bundled` and `Linked` entries; validation
  errors raise `CatalogError("OAH_TOOLKIT_CATALOG_INVALID", ...)` (exit 69).
- `validate_repository(url)` — `https://` without user info, query or fragment, or a local path.
- `Upstream` (UPSTREAM.json): `name, repository, subpath, ref, commit, spdx, license_path,
  license_file, license_sha256, notice_files, executables, files {path: git blob id}, fetched`.
- `kit_skills_dir(env) -> Path | None`; `item_skill_dirs(item_dir, bundled) -> list[Path]`.
- Tests: `test_shipped_catalog_is_valid`, `test_catalog_rejects_credentials_in_urls`,
  `test_vendored_items_have_provenance` (provenance gate), `test_vendored_files_are_upstream_blobs`,
  `test_every_vendor_row_is_bundled_or_link_with_reason`.

### Task 3: Fetch and stage — `src/oah/toolkit/fetch.py`

- `fetch(repository, ref, scratch, *, paths=(), timeout) -> Tree` — isolated `git init` and
  `fetch --depth 1 <ref>`, without checkout; returns object-store access at `FETCH_HEAD`.
- `stage_item(bundled, tree, dest, *, fetched) -> Upstream` — validates all upstream paths for portable
  collisions and reserved names, refuses selected symlinks/submodules, and copies the subpath, the
  license and notice files, keeps executable bits, writes `UPSTREAM.json`; refuses when the license
  text's SPDX id is not the expected one or staged bytes differ from the blob manifest.
- Tests (local fixture repositories made in temp folders): `test_fetch_and_stage_records_provenance`,
  `test_stage_refuses_wrong_license`, `test_fetch_never_prompts_for_credentials`.

### Task 4: Checks — `src/oah/toolkit/checks.py`

- `identify_license(text) -> str | None` (MIT, Apache-2.0, BSD-2/3-Clause, ISC), `text_digest(bytes)`
  (LF-normalized SHA-256).
- `diff_summary(old_dir, new_dir) -> DiffSummary(files_changed, added, removed)`.
- `privacy_problems(folder, *, gitleaks) -> list[str]` — built-in key shapes and absolute home paths,
  plus `gitleaks detect --no-git` when installed; a gitleaks error is a problem.
- `suspicious(old, new, old_dir, new_dir, *, size_jump_ratio, size_jump_min_bytes) -> list[str]` —
  license change, new executable, binary blob, size jump.
- Tests: `test_identify_license`, `test_diff_summary_counts_lines`, `test_privacy_finds_keys_and_paths`,
  `test_suspicious_new_executable_binary_and_size_jump`.

### Task 5: Install and list — `src/oah/toolkit/install.py`

- `target_dirs(targets, level, *, project_root, home) -> list[Path]`.
- `plan_install(names, *, catalog, bundle_dir, targets, level, project_root, home) -> InstallPlan`
  (each copy is `install`, `replace` (an oah-installed copy) or `conflict` (a folder oah did not
  install)); `apply_install(plan, *, now)`; `plan_linked(linked)` and `run_linked(linked, *, runner)`.
- `list_rows(*, catalog, bundle_dir, project_root, home) -> list[Row]` — bundled, linked, installed.
- Tests (`tests/test_skills_cli.py`): `test_list_shows_bundled_linked_and_installed`,
  `test_install_project_copies_skill_license_and_marker`, `test_install_user_needs_consent`,
  `test_install_dry_run_writes_nothing`, `test_install_refuses_foreign_folder`,
  `test_install_linked_runs_official_command_with_consent`, `test_linked_manual_steps_are_printed`.

### Task 6: Updates — `src/oah/toolkit/update.py`

- `run_update(*, catalog, destinations, state_dir, check_only, settings, fetcher, now) -> list[UpdateResult]`
  with statuses `current`, `available`, `advanced`, `rolled-back`, `failed`, `deferred`.
- `active_leases(state_dir)` via `Store(state_dir).snapshot()`; `due(state, now, interval_days)`;
  `maybe_scheduled_update(...)`; state in `<state>/toolkit/updates.json` under a `StateLock` at
  `<state>/toolkit/.lock`.
- Tests (`tests/test_skills_update.py`, update-rollback gate): `test_update_advances_pin`,
  `test_update_rolls_back_on_license_change`, `test_update_rolls_back_on_failed_load_check`,
  `test_update_rolls_back_on_suspicious_file`, `test_update_rolls_back_on_privacy_hit`,
  `test_update_defers_while_lease_active`, `test_check_only_writes_nothing`,
  `test_scheduled_runs_at_most_once_per_interval`, `test_failed_swap_restores_backup`.

### Task 7: OS scheduler — `src/oah/toolkit/schedule.py`

- `launchd_plist(...) -> bytes`, `task_xml(...) -> str`, `install_entry(...)`, `remove_entry(...)`,
  `entry_status(...)`, with an injectable runner (`launchctl bootstrap|bootout`, `schtasks /Create /XML
  | /Delete`).
- Tests: `test_plist_runs_scheduled_update`, `test_task_xml_runs_scheduled_update`,
  `test_schedule_install_and_remove_with_fake_launchctl` (POSIX), `test_schtasks_xml_is_utf16` (Windows).

### Task 8: CLI — `src/oah/skills_cli.py`

- `COMMANDS = ("skills",)`; subcommands `list [--json]`, `install <name>|--all [--target
  claude|codex|both] [--user|--project] [--dry-run] [--yes]`, `update [--check] [--yes] [--scheduled]
  [--vendored]`, `schedule install|remove|status [--yes] [--user]`.
- Tests drive `register` + `run` with an `argparse` parser and temp `HOME`/project folders.
