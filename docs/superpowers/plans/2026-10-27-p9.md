# P9 Beginner Docs, Worked Example and Troubleshooting Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A newcomer reads the README, installs `oah`, runs `oah init` and follows `examples/hello-oah`
through the whole loop. Concepts, troubleshooting, upgrade and keys each have one page in English and
Korean, and two tests keep the docs from drifting away from the code.

**Architecture:**
- **Docs:** `README.md` (English, with a Korean section of the same structure), `docs/<page>.md` and
  `docs/ko/<page>.md` for concepts, troubleshooting, upgrade and keys. Existing install, CI starter and
  companion pages get only stale-status fixes.
- **Example:** `examples/hello-oah/` holds a tiny Python program, its tests and two READMEs
  (`README.md`, `README.ko.md`) that walk the loop with real commands.
- **Tests:** `tests/test_docs.py` checks the docs against `src/oah/`; `tests/test_example_hello.py` runs the
  walkthrough's `oah` commands with fake engines.

**Tech Stack:** Python 3.11+ stdlib (`unittest`, `re`, `shlex`), the existing fakes in `tests/fakes/`
and the in-process CLI runner and stub `node` in `tests/fixtures/gates/support.py`.

**Spec:** `docs/PLAN.md` sections 3, 5.3, 6.5, 8, 9 and 15 (P9 checklists A9–A17, OB, A20, A21, C5;
the Release checklist).

## Global Constraints

- No code under `src/oah/` changes. Wrong behaviour found while writing is reported, not fixed.
- Every command shown in a doc was run, or read from its parser and tests, on `main` plus the P6b
  (`oah fix`) and P7b (`oah init`) branches. Statements about those two commands are rechecked after the
  coordinator rebases this lane.
- No key, token or account identifier appears anywhere; examples use `${NAME}` placeholders only.
- No personal paths, user names or machine details; the privacy scan stays clean.
- Korean sentences never end with a colon.
- No document claims a fixed effort cap (C5); effort text follows A1.

## Review Focus

- Accuracy: every `OAH_*` code and command named in the docs exists on `main` (after the rebase).
- The walkthrough test runs the same `oah` commands, in the same order, as both example READMEs.
- Status text says what works today; no per-lane change log remains in the README.

## Task 1: `tests/test_docs.py`

- `test_listed_codes_exist`: every `OAH_[A-Z0-9_]+` code in `docs/troubleshooting.md` and
  `docs/ko/troubleshooting.md` appears in some `src/oah/**/*.py`. A helper `missing_codes(doc_text, src_root)`
  takes the source root as a parameter.
- `test_renamed_code_fails`: copies `src/oah` to a temp folder, renames one listed code there and
  expects `missing_codes` to report it.
- `test_troubleshooting_pages_list_the_same_codes`: the English and Korean pages list the same codes.
- `test_codes_in_other_docs_exist`: the codes named in `README.md`, the P9 pages and the example READMEs
  exist in `src/oah/`.
- `test_no_fixed_effort_cap`: no `README.md` or `docs/**/*.md` text (except `docs/PLAN.md` and
  `docs/superpowers/`) matches a fixed-cap pattern such as "max is rejected" or "effort is capped".
- `test_every_page_has_a_korean_twin`: each P9 page has `docs/ko/<page>.md`, and the example has
  `README.ko.md`.
- `test_relative_links_resolve`: relative Markdown links in `README.md`, `docs/*.md`, `docs/ko/*.md` and
  the example READMEs point at files that exist.
- `test_korean_sentences_do_not_end_with_a_colon`: in the Korean pages this lane writes, no prose line
  ends with Hangul followed by `:`.
- `test_keys_page_names_the_lookup`: the keys pages name `TYPESAFE_API_KEY`, `unused(no key)` and
  `codex login --with-api-key`.

## Task 2: `examples/hello-oah` and `tests/test_example_hello.py`

- The project: `hello.py` (`greet()` returns `Hello, world!`) and `tests/test_hello.py`.
- The task `hello-name`: `python hello.py Ada` prints `Hello, Ada!`. The fake reviewer reports that an
  empty name prints `Hello, !`; the fake corrector makes it fall back to `world`.
- `readme_commands(path)`: the `oah ...` lines of the README's `sh` blocks, in order.
- `test_readmes_list_the_same_commands`: English and Korean READMEs list the same commands
  (runs on every branch).
- `test_walkthrough_runs_end_to_end`: copies the example to a temp folder, makes a local bare remote,
  points the config at `fake_claude.py` and `fake_fix_codex.py`, stands in for unlazy with the stub `node`,
  runs every README command in order through the real command discovery and checks each result line. It
  then asserts that the commands it ran equal the README's list. It skips only while `oah fix` or
  `oah init` is not on the branch (P6b, P7b).
- The offline test uses the documented local practice alternative and checks refusal with no gitleaks or
  gh; a separate real-process gh stand-in verifies that local destinations refuse CI when gh is present.
  These tests do not certify the GitHub landing route or CI.

## Correction C1 decisions

- F1: Both walkthroughs tell readers to append bytecode ignores before gates; a portable test executes both
  real Python CHECK commands, proves bytecode was created and checks that the gate input digest stays equal.
- F2: GitHub creation and push commands are the landing route. Local bare remotes are practice through finish;
  gh cannot query their CI and its refusal remains intact. Tests explicitly bound their offline coverage.
- F3: Wiki maintenance precedes the final gate check, commit and review, including after a correction, so
  tracked wiki writes cannot invalidate passing gate inputs. The walkthrough test follows that order.
- F4: The empty-name finding is illustrative. Live users follow convergence, changes-requested or
  decision-required outcomes rather than running a correction unconditionally.
- F5: Existing incompatible project unlazy copies require manual backup/removal and override repair before
  init; `--force` is not a repair and can reset config. English and Korean upgrade instructions agree.
- F6: Packet generation writes Plan; call-time routing reads it and records `--tier` overrides in run state.
- F7: Both upgrade pages explain MCP discovery, check-only versus persisted notices, offline doctor display
  and manual pin edits. The diagnostic check permits only P7m's exact new code while its notice reader is absent.
- The known finish-crash skip remains unchanged pending fx2. No source modules or installer behavior change.
