# P7a Wiki, Rules Block and Graph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Project knowledge survives between sessions. `oah wiki` keeps an Obsidian-compatible
`docs/wiki/` honest (A8), `oah rules` puts one shared rules block in `AGENTS.md` that `CLAUDE.md`
imports, and `oah graph` passes through to graphify when it is installed.

**Architecture:**
- `oah.wiki` is a package. Core functions take a `WikiSettings` value and never read the config file;
  `wiki_cli.py` and `hook_pre_commit.py` build it from `load_config(root).section("wiki", DEFAULTS)`.
- Every wiki command takes one exclusive wiki lock, `<state>/wiki/.lock` (`oah.lockfile.StateLock`,
  separate from the lease lock), and checks the rollover journal `<state>/wiki/rollover-journal.json`
  before reading or writing anything.
- Rollover parses `log.md` as bytes, moves whole entries, journals both replacement files and
  publishes archive-first. `oah wiki recover` is the only command that completes or reconciles a
  pending journal.
- `oah.hook_pre_commit.run(args)` checks the staged tree against `HEAD` through git plumbing.
- `oah.rules` owns one marker block in `AGENTS.md` and one `@AGENTS.md` line in `CLAUDE.md`.
- `oah.graph` resolves `graphify` through `oah.engines.proc` and never runs it on its own.

**Tech Stack:** Python 3.11+ stdlib (`importlib.resources`, `hashlib`, `base64`, `unittest`), git
through `oah.engines.proc`.

**Spec:** `docs/PLAN.md` 5.1, 5.10 (wiki, A8), 5.11, 5.12 (pre-commit row), 4 rows 19–21, 15 (P7
checklist for A8), and the lane intent (A12, A17).

## Global Constraints

- Everything from the P1 and P2 plans still applies: stdlib only, never `shell=True`, UTF-8 stated on
  every read and write, parsers accept CRLF, a Korean one-line header on new `.py` files, test writes
  inside the checkout, executables resolved through `oah.engines.proc`.
- **Command modules** expose `register(subparsers)`, `COMMANDS` and `run(args) -> int`:
  `wiki_cli.COMMANDS = ("wiki",)`, `rules_cli.COMMANDS = ("rules",)`, `graph_cli.COMMANDS = ("graph",)`.
  `cli.py` is not edited here; `oah.cli` discovers the modules and tests call `oah.cli.main`.
- **Exit codes:** 0 ok, 1 refused (problems found, refused writes), 2 usage, 69 environment (not a
  repository, wiki folder missing, lock timeout, unreadable state).
- **Settings** (`oah.wiki.DEFAULTS`, the future `[wiki]` section):
  `dir = "docs/wiki"`, `link_roots = []`, `index_line_limit = 120`, `stale_days = 180`,
  `rollover_trigger_bytes = 512000`, `rollover_target_bytes = 409600`, `new_broken_links = "warn"`.
- **System pages:** `index.md`, `index_archive_*.md`, `log.md`, `log_archive_NN.md`. They are index or
  log sources, not notes: no frontmatter, source, orphan, stale or index checks apply to them, but
  their links are checked. `templates/`, `raw/` and dot-folders (such as `.obsidian/`) are not notes.
- **Index sources** are `index.md`, every `index_archive_*.md`, and the generated archive-index table
  in `log.md`. A note is indexed when an index source links to it.
- **Candidates only (A8):** no wiki command deletes, merges or moves a note. Lint output and the
  `--index` candidate file are the only results of a scan.
  Code masking recognises code spans, top-level fences and indented code blocks only. Fences nested
  in lists or blockquotes are not parsed; their links may appear as candidates. Inspect candidates
  before editing notes. A conservative list hint survives lazy paragraph continuations and skips
  ambiguous indented delimiters, so a nested fence cannot hide a following real link or log entry.
  Thematic breaks take precedence over list markers. `oah wiki lint --help` states this limit.
- **No keys (A17):** templates and tests contain no credentials; the rules block says so.

## Review Focus

1. **Rollover never loses or duplicates a log entry.** The preservation stream (log entries, then
   archives newest first) is byte-identical before and after, including CRLF files, fenced `## `
   lines, oversized entries and multiple archives. → Task 2 `test_stream_preserved_*`.
2. **A crash at any publication step is recoverable exactly once.** → Task 3
   `test_fault_at_every_step_then_recover`, `test_recover_twice_is_idempotent`,
   `test_recover_conflict_preserves_everything`.
3. **A pending journal freezes the wiki.** Lint, log, new, rollover and hygiene refuse with
   `OAH_WIKI_RECOVERY_PENDING` and leave every byte unchanged. → Task 3
   `test_pending_journal_blocks_every_command`.
4. **Lint counts only real problems** (link roots, code spans and blocks, archive indexes, commit
   dates). → Task 4.
5. **Rules sync writes only the block**, keeps line endings, refuses broken or duplicate markers and
   links, and never touches global files. → Task 7.

  Template lookup: `<wiki>/templates/<kind>.md`, then the packaged template. Exclusive create; refuses
  `OAH_WIKI_NOTE_EXISTS` when any note already has that file name (case-insensitive). Adds

### Task 9: `oah wiki maintain --task` and `verify_maintenance` (coordinator note 2, PLAN 5.10 delta)

**Interfaces:**
- `oah wiki maintain --task T [--title …] [--body …]` → `Wiki.maintain_task(task, title, body, steps)`.
  Under one wiki lock: a log entry whose first body line is the hidden marker `<!-- oah-task: T -->`,
  a `- task T: <title>` line under the `Tasks:` label of `index.md`, then size-based rollover. Each
  part is found by its marker first (log.md and every archive), so a retry or a run after rollover
  completes only missing work. Lock contention waits up to `lock_timeout` (10 s), then refuses
  `OAH_WIKI_BUSY`; a pending journal refuses `OAH_WIKI_RECOVERY_PENDING`.
- On success one JSON line is appended to `<state>/wiki/maintenance.jsonl` (`oah.atomic.append_jsonl`):
  `{version, task, worktree, at, outputs{repo-relative path: sha256}, steps}`; outputs are only
  `log.md`, `index.md` and a newly created `log_archive_NN.md`.
- `oah.wiki.maintain(root, on=…, task=T)` runs the same steps (`index` needs a task).
- `oah.wiki.verify_maintenance(root, task) -> MaintenanceCheck(ok, problems, record, lint, hygiene)`:
  exactly one marked entry, exactly one index line, and the latest record of this worktree matching
  the current bytes (`OAH_WIKI_MAINTENANCE_MISSING` / `OAH_WIKI_MAINTENANCE_STALE`), plus read-only lint
  and hygiene (no baseline stored). A later change to `log.md` or `index.md`, including another task's
  maintenance, makes the record stale until maintain runs again.

- [ ] Tests in `tests/test_wiki.py` `MaintainTaskTest`: CLI record and digests, idempotency, retry after
  partial work, idempotency after rollover, new archive in the record, lock contention, pending
  journal, task id validation, verify missing/ok/stale, removed entry or index line, other worktree.

### Task 10: Safer log rollover (coordinator notes 3–5, amendment 4 / A18)

- **Refusals:** every invalid log refuses `OAH_WIKI_LOG_INVALID` before any write; the message names the
  case ("no marker", "undated first entry heading", "unclosed code fence", …).
- **Hashes:** `RolloverPlan.entries_sha256` is the sha256 of log.md's entry bytes; kept plus moved byte
  slices must hash the same before anything is written.
- **Revalidation:** under the wiki lock, before publication the log must keep its identity (device, inode,
  size, mtime) and bytes, or the run refuses `OAH_WIKI_CONCURRENT_EDIT` before publishing anything.
  After publication both files are re-read. Only the exact published file and bytes, the archive's
  bytes and an unchanged preservation stream let the journal go.
- **No automatic restore (coordinator note 7):** any other result touches no file. The journal records
  the live bytes (`current_log`, `current_archive`) with phase and reason `changed-after-publication`,
  and every command refuses `OAH_WIKI_RECOVERY_PENDING`. `oah wiki recover` refuses
  `OAH_WIKI_RECOVERY_CONFLICT`, naming the files that differ and the journal.
- **`oah wiki recover --resolved`** reconciles every `OAH_WIKI_RECOVERY_CONFLICT`, including the earlier
  5.10 one. After a manual fix it checks that log.md and every archive parse and that no entry appears
  twice across them (entry bytes compared with CRLF folded and trailing whitespace dropped). Otherwise it
  refuses and changes nothing. When the checks pass it never deletes journal bytes (coordinator note 8).
  - It lists every entry that the journal's original snapshot or captured live bytes contain but the
    reconciled files lack (`OAH_WIKI_RECOVERY_DROPPED`). The list never blocks.
  - It moves the journal unchanged to `<state>/wiki/resolved-records/rollover-journal-<UTC time>.json`.
  - It appends a record (resolved journal path, dropped entries) to `<state>/wiki/recovery-resolutions.jsonl`.
- **CLI:** `oah wiki rollover` is a dry run printing `OAH_WIKI_ROLLOVER_PLAN …`; `--apply` needs an active
  lease of this worktree covering `log.md` and the new archive, else `OAH_WIKI_LEASE_REQUIRED`.
  `oah wiki maintain` applies rollover under the wiki lock without a lease, with the same checks.
- **Config:** `[wiki] rollover_trigger_bytes = 512000` and `rollover_target_bytes = 409600`. The archive
  name stays fixed (`log_archive_NN.md`), because the 5.4 scope exemption, lint and recovery depend on it
  (coordinator note 6).
