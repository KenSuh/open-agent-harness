# P7m MCP Template Pins With Update Notices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every npm-pinned MCP template in `mcp/` is listed in the toolkit catalog, and the existing
skill update check tells the user and the kit maintainer when npm publishes a newer version. Pins
stay pins: oah only notifies and never edits a template, the catalog or a user's MCP config.

**Architecture:**
- **Catalog:** `upstreams.json` gains an `mcp` list read by `oah.toolkit.catalog` into `Mcp` entries
  (`Catalog.mcp`). Readers of `bundled`, `linked` and `clis` are unchanged, and `Catalog.find` still
  returns skills and plugins only.
- **Query:** a new `oah.toolkit.npm` module asks the npm registry for `<package>/latest` with
  `urllib` (standard library). Proxies come only from the allowlisted environment that skill fetches
  use (`oah.toolkit.fetch.git_env`, which refuses a proxy with embedded credentials). No cookies,
  no auth handlers, no redirects, a size cap and the skill fetch timeout.
- **Result kind:** `oah.toolkit.update.run_update` gains `mcp=` entries and an injectable `registry`
  query. It appends one `UpdateResult(kind="mcp")` per entry after the skill results, so the same
  printing, exit codes, `updates.json` run record and `updates.jsonl` log apply. No second updater.
- **Doctor:** `oah doctor` reads `updates.jsonl` (no network) and shows the last notice per catalog
  entry whose new version is still above the catalog pin.

**Tech Stack:** Python 3.11+ stdlib (`urllib.request`, `http.server` in tests, `json`, `tomllib`).

**Spec:** `docs/PLAN.md` 5.2, A13, A15, A23; lane intent p7m (AC1 to AC7).

## Global Constraints

- Everything from the earlier plans still applies: stdlib only, never `shell=True`, UTF-8 on every
  read and write, a Korean one-line header on new `.py` files, tests never reach the network.
- **Owner invariant: pins stay pins; oah only notifies.** No code path writes `mcp/`, the catalog or
  any user MCP config because of a registry answer. A test snapshots all three around a notice.
- **Registry values are untrusted.** A version is printed or logged only after it matches a strict
  semver pattern (at most 64 characters). Any other answer (bad JSON, wrong package name, oversized,
  non-semver) is `unused(registry error)` with the field named, never echoed.
- **Offline never fails a command.** An unreachable or slow registry gives `unused(offline)` for that
  entry; the other entries and the skill results continue, and the exit code ignores MCP results.
  `oah skills update` has no `--offline` flag, so none is added.
- **Network exception (A23):** the only new network contact is `https://registry.npmjs.org`, from
  the same commands that already fetch skills. The registry base is a module constant, not config.
- **Removed (owner decision 2026-10-25):** `korean-law` leaves `mcp/`, `mcp/README.md`,
  `docs/toolkit.md` and the tests. The A13 inventory row in `docs/PLAN.md` stays (not this lane's
  file); the toolkit tests skip names in an explicit `REMOVED_BY_OWNER` set.

## Review Focus

- The MCP query cannot send a credential: allowlisted proxies only, no redirect following, no auth.
- Untrusted registry text never reaches stdout, the log or doctor output unvalidated.
- MCP results never change skill exit codes, deferral or rollback, and never become `deferred`.
- The consistency test really fails when one pin changes in only one of template, catalog or page.
