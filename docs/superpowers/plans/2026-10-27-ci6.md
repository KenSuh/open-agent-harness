# CI6 Method-Level Test Shards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI shards are split by test method, not by class, so no single class can outgrow a shard;
the job timeout stays 45 minutes and the shard count stays 5.

**Architecture:**
- **Units.** `tools/test_shard.py` cuts the discovered suite into single test cases. A custom suite (any
  suite whose type is not plain `unittest.TestSuite`) stays one unit, as today.
- **Assignment is unchanged.** Units are placed largest first, ties in discovery order, each on the shard
  with the fewest tests so far, ties to the lowest shard. With single-test units this deals the tests of
  every class round-robin over the shards, so a class's methods (and its run time) spread evenly.
- **Order.** Each shard runs its units in discovery order, so a class's methods stay adjacent and
  unittest runs `setUpModule`/`setUpClass` once per shard that holds them, and tears them down at the
  shard's end or when the next class or module begins.

**Tech Stack:** Python 3.11+ stdlib (`unittest`, `importlib`, `subprocess`).

**Spec:** `docs/PLAN.md` (8) and the CI shard history in PRs #29, #38, #40 and #41; the lane intent
`ci6` r1 in the dispatch brief is authoritative.

## Global Constraints

- Everything from the earlier plans' Global Constraints still applies: stdlib only, never
  `shell=True`, UTF-8 on every read and write, test writes inside the checkout.
- No timing table: balancing stays by test count (non-goal).
- `.github/workflows/ci.yml` keeps `shard: [1, 2, 3, 4, 5]` and `timeout-minutes: 45`; only its
  comments change.
- The command line (`python tools/test_shard.py INDEX COUNT [unittest options]`) and `shards()`'s
  signature do not change.

## Review Focus

- Every discovered test runs exactly once across the shards, for every COUNT.
- Fixtures: module and class set-up and tear-down run once in each shard that holds their tests, never
  in a shard that holds none, and are torn down at the shard's end.
- Custom suites from `load_tests` stay intact and run their wrapper once.
- Determinism: two runs compute identical shards.

## Interfaces

- `shards(count, tests_dir=ROOT / "tests", loader=None) -> list[list[unittest.TestSuite]]`: unchanged.
- `_units(suite)`: yields a custom suite intact, and every other test case as `TestSuite([case])`.
