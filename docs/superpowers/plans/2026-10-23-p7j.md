# P7j Default-Branch Impact Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** before a query, `oah impact` fetches the remote's default branch read-only and refreshes a
second persisted map for the fetched commit, next to the worktree map. The output names both maps by
commit SHA and merges their rows without duplicates, marking rows found only on the default branch.
Offline, disabled or failed refreshes fall back to oah's last recorded branch and SHA, always labelled.

**Architecture:**
- **`oah.impact.defaultbranch`** finds the remote and confirms its symbolic HEAD online, fetches the
  branch into a new private bare generation at
  `<state>/impact/mirrors/<worktree key>.generations/mirror-<random id>`, and returns a
  `DefaultBranch` result (state `fresh | stale | unavailable`, reason, remote, branch, commit, map info
  and data). One stable per-worktree OS lock covers preparation, discovery, fetch, SHA capture and map
  build; CLI queries keep it until their last search finishes. No fetch runs in the user's repository.
  A generation is never fetched into twice. After a successful fetch, SHA capture and map build, an
  atomic `current.json` pointer publishes its generation name and captured SHA. Failed, timed-out or
  interrupted fetch generations are never published or reused. Git lock files are not inspected or repaired.
  A subprocess owns each generation's separate OS lease while Git runs, reaping its process tree on
  cancellation, timeout or parent exit. Generation reads use this same ownership protocol. Cancellation
  markers identify individual commands; only their owner clears them after stopping, so delayed owners
  stay cancelled without preventing later reads of a published generation. Cleanup
  acquires the lease and marks retirement before removing a generation, so a late-starting owner cannot
  write a retired directory. Current and recorded-map generations remain available through reads and
  failure fallback; cleanup keeps at most the current generation plus one pending cleanup. A pending
  cleanup blocks further allocation until it can finish. A map/pointer publication gap is reconciled
  to the recorded snapshot before the next allocation. Legacy unleased caches are read-only fallback
  sources and are left untouched; they are never fetch destinations or deleted on presumed abandonment.
- **`oah.impact.mapstore`** gains the ref map: `ref_map(root, ref, *, refresh, env, settings)` stores
  `<state>/impact/maps/<worktree key>.default-branch.json` beside the worktree map, under the same lock
  (`<state>/impact/.lock`). Its manifest is `worktree`, `ref`, `head` (the fetched SHA) and `tool`; its
  inputs are the `blob:<oid>` keys from `git ls-tree`. The private `_ref_map` helper reads objects from
  the mirror while binding the manifest to the original worktree; `ref_map` keeps its public signature
  and existing local-ref behavior. Mirror maps also record the remote name (never its URL).
  The mirror caller supplies the captured immutable SHA to `_ref_map`; the manifest retains the
  named remote ref for labels, while every map input is read from that SHA.
  Freshness uses the same `_judge` and result digest; refresh uses the same `refresh_data`, generalised
  with `rev=` so it reads blobs at the commit. An incremental refresh equals `build_data(mirror, sha)`
  byte for byte. Pre-mirror recorded maps remain usable offline; missing-target searches may read their
  already fetched objects from the user's repository until a successful mirror refresh.
- **`oah.impact.query.merge_maps`** merges the worktree rows with the default-branch rows. Two rows are
  the same when `(binding, layer, source, line, target)` match; the worktree row is kept. Each row is
  marked `both`, `worktree` or `default-branch`. The single re-ranker call site is unchanged and runs on
  the merged rows.
- **`impact_cli`** adds `--offline`, prints `maps: worktree=<sha> default-branch=<sha|stale(…)|
  unavailable(…)>` and a JSON `maps` object, and marks default-branch-only rows. Actions (`build`,
  `refresh`, `status`) and `ensure_fresh(root)` never fetch. Explicit paths expand against each map
  separately, then the selections are unioned, so a file cannot mask a directory in the other map.
  Task-Scope selections use the union of both maps' files with the existing kind filters. Searches for
  targets absent from the default map read the mirror at the recorded SHA.

**Tech Stack:** Python 3.11+ stdlib, git through `oah.paths.git_argv`, `oah.engines.proc.run_command` and
a leased subprocess owner using the existing process-group / Windows Job cleanup primitives.

**Spec:** `docs/PLAN.md` 5.10 ("The latest default branch (A23)"), A23 in amendment 5, section 15 P7j;
lane intent p7j.

## Global Constraints

- Everything from the P1, P2 and P7i plans' Global Constraints still applies.
- **Remote:** the current branch's `branch.<name>.remote` when it names a configured remote, else
  `origin` when configured, else none (`stale(no remote)` with a saved map, otherwise unavailable).
- **Default branch:** every online refresh asks `git ls-remote --symref <url> HEAD` from the mirror.
  A local remote HEAD never confirms the remote's current default. Successful output without a valid
  `refs/heads/...` symbolic HEAD is `default branch lookup failed`; no fallback branch is fetched.
  Fresh means this run confirmed the remote's symbolic HEAD and successfully fetched and mapped that
  branch. Every other case uses the last recorded map's branch and SHA, including a saved branch from
  before a remote default change or removal. Manifest/result digests and worktree identity are checked;
  mutable user or mirror tracking refs never replace this recorded snapshot. Without a recorded map,
  the result is unavailable even if the user's clone has remote-tracking refs.
- **The fetch (A17, AC4):**
  `git --git-dir=<mirror> -c core.askPass= -c core.logAllRefUpdates=false -c gc.auto=0
  -c maintenance.auto=false -C <mirror> fetch
  --quiet --no-tags --no-recurse-submodules --no-write-fetch-head --no-prune --end-of-options <url>
  +refs/heads/<b>:refs/remotes/<r>/<b>`. The mirror is initialized bare with an empty template and the
  user's repository object format (SHA-1 or SHA-256).
  Its Git directory is explicit for every discovery/fetch command, so an incomplete generation cannot
  make Git discover and write the user's parent repository. Every fetch initializes a new generation.
  The remote's URL is the first stored value from `git config --null --get-all remote.<name>.url`, excluding local
  `insteadOf` expansion. The mirror resolves system/global aliases with the non-network
  `git ls-remote --get-url` before relative local URLs are resolved against the user's checkout.
  Network commands use system/global Git config, credential helpers and SSH,
  without the user's repository config or inherited repository/config overrides. The URL is never
  saved as a mirror remote. `oah-source.json` stores only a digest of the stored/resolved URL pair,
  the selected ref and the captured commit; it never contains URL bytes. User refs, objects, config and FETCH_HEAD stay
  byte-identical by construction, including with configured ref mappings or incremental bundle URI lists. Per-option refmap, bundle URI
  and remote-HEAD guards are unnecessary and removed. FETCH_HEAD, reflogs and Git tracing are suppressed
  in the mirror so a credential-bearing URL cannot enter state or logs. Automatic Git maintenance is
  disabled during fetch. The generation owner also stops and reaps Git on interruption or parent exit;
  its lease prevents removal while a command still uses the generation. stdin is closed and the Git
  timeout is `[impact] git_timeout`.
  Both discovery and fetch set `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, empty `GIT_ASKPASS` and
  `SSH_ASKPASS`, `core.askPass=`, and `SSH_ASKPASS_REQUIRE=never`. They force the OpenSSH variant with
  `ssh -oBatchMode=yes -oNumberOfPasswordPrompts=0 -oStrictHostKeyChecking=yes`, overriding interactive
  SSH commands and wrappers. OpenSSH host/key configuration and agents still apply; users of custom
  wrappers can configure OpenSSH or fetch manually and query with `--offline`. This A23 unattended
  behavior prevents login and host-key dialogs. Git handles credential helpers itself; oah neither
  inspects their output nor persists credentials, and never prints Git's stderr (it could hold a URL).
- **Labels (AC3):** `fresh` → `default-branch=<sha>`; otherwise `default-branch=stale(<reason>)` with
  `last-fetched=<sha>`, or `default-branch=unavailable(<reason>)` when no fetched ref exists. Reasons:
  `offline`, `refresh_default_branch=false`, `no-refresh`, `no remote`, `fetch failed`,
  `fetch timed out`, `default branch lookup failed`, `cache cleanup pending`. The last reason asks the
  user to wait for the earlier query, check cache permissions and retry. A map build failure also falls back with its safe
  error code. Stale and unavailable also print an
  `OAH_IMPACT_DEFAULT_BRANCH_STALE` / `OAH_IMPACT_DEFAULT_BRANCH_UNAVAILABLE` warning on stderr that says
  what to do. The query never fails because of the network.
- **`--no-refresh`** fetches nothing and builds nothing: the validated recorded default-branch map is
  used as `stale(no-refresh)`, otherwise `unavailable(no-refresh)`. Offline and disabled refresh use
  exactly the same saved snapshot rule, retaining the specific reason in text and JSON.
- **DB entities:** an entity unknown to the default-branch map is skipped there (it is new in the lane);
  one unknown to the worktree but known on the default branch is answered from it. Only when neither map
  knows it does the query refuse as before. When the default branch has a DB graph, JSON `db_impact.maps`
  names each available graph by `worktree` or `default_branch`, with its own `commit` and `graph` digest.
  `merged_output` hashes the printed DB rows, including `found_in`; text prints the same map identities
  and `merged-output`. This A23 output change prevents attributing combined rows to one commit. Without
  a default-branch DB graph, P7i's existing `commit`, `graph` and `output` format remains unchanged.
- **Coverage warnings:** default-map symlink exclusions and unparsed SQL warnings reach stderr and the
  top-level JSON `warnings`, labelled with the source map and its commit. Worktree warnings keep P7i's
  format. This A23 addition makes missing coverage visible even when the fetched map is fresh.
- The gate layer stays as P7i left it (`gatebind.discover` reports unavailable), and gates are queried
  once, from the worktree. Rows newly bound on the default branch come from the lexical layers (workflow,
  manifest and config commands give pin and exec).

## Review Focus

- A fetch never targets the user's repository: snapshot all its Git files except oah state, including
  refs, objects, config and FETCH_HEAD, and compare bytes after querying. An incremental bundle-list
  positive control proves the fixture would otherwise alter bundle refs and configuration.
- `--offline`, `refresh_default_branch = false` and `--no-refresh` start no `git fetch` and no
  `git ls-remote` (checked at the process runner as well as the non-network `GIT_TRACE` output).
- Only current-run symbolic-HEAD confirmation plus a successful fetch is fresh. Offline, disabled,
  no-refresh, lookup failure, absent symref, fetch failure and timeout all retain the recorded branch
  and SHA, or return unavailable when never recorded. Test both text and JSON, including changed
  default branches and independently moved local tracking refs.
- Ref-map incremental refresh equals a full build at the fetched SHA.
- Merging never drops a pin or exec row and never prints the same row twice.

## C7 correction and acceptance

- The no-remote path already avoided fetch, but acquired the mirror lock before checking remotes;
  contention could therefore consume the default 120-second lock timeout without any remote to fetch.
  The new portable subprocess regression holds that lock and failed before the correction. Both the
  API and CLI now bypass it when neither a usable remote nor a recorded map exists, returning
  `default-branch=unavailable(no remote)`. Empty remote lists also skip branch/upstream subprocesses;
  a second regression failed on those unnecessary commands before the correction. The reported
  168-second Windows run cannot be reproduced here because native Windows is unavailable.
- A23 operations reuse repository root/common-directory locations within one context, removing
  repeated four-command repository discovery during mirror preparation, cleanup and searches.
  Refs, HEAD, configuration, maps and freshness inputs are not cached. State-directory overrides
  are evaluated on every lookup; a regression checks one discovery per refresh and a distinct map
  under a changed override on the next refresh. Mirror map construction still checks the live local
  HEAD and preserves the existing no-commit refusal; a late regression caught its omission during
  the optimization, and passes after restoring the check. Local P7i map operations retain their existing path.
  With a recorded map and a removed remote, the existing `stale(no remote)` fallback and its mirror
