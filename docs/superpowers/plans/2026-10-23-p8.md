# P8 Installers, Guided Tool Setup and Tool Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A beginner runs one command per OS from a clone. It finds or fetches Python, hands over to
a guided, consent-based tool setup, installs `oah`, checks PATH and finishes with `oah doctor`.
The tool catalog behind the setup is the one `oah doctor` and `oah init` (lane P7b) use.

**Architecture:**
- `oah.setup` (a package) holds the single tool catalog and the guided installer. Core functions take
  their collaborators (`which`, `confirm`, `runner`, `status_runner`) as parameters; nothing reads
  config.
- The shell scripts do only what Python cannot do for itself: find Python 3.11+ (offering uv when it
  is missing), run `python -m oah.setup` from the clone's `src/`, install `oah`, check PATH, and run
  `oah doctor`.
- `oah doctor` builds its rows from the same catalog and keeps `doctor_main(json_output=...)`.

**Tech Stack:** Python 3.11+ stdlib, bash 3.2, Windows PowerShell 5.1 / PowerShell 7.

**Spec:** `docs/PLAN.md` 5.3, 5.13, 6, 8, 9, 13, and the lane intent (`p8` r1, amendment 3 items).

## Global Constraints

- Everything from the P1 and P2 plans still applies: stdlib only, never `shell=True`, UTF-8 on
  every read and write, a Korean one-line header on new `.py` files, test writes inside the checkout.
- **Official commands only.** Each catalog entry carries the command text from PLAN 6.1 (plus jq and
  rg from their official pages). A shell one-liner runs through an explicit interpreter argv:
  `["/bin/sh", "-c", text]` or
  `["powershell", "-NoProfile", "-ExecutionPolicy", "Bypass", "-Command", text]`. The exact text is
  shown before the question.
- **Consent.** Nothing is installed without a per-tool `y` or `--yes`. `--dry-run` / `-DryRun` runs
  only read-only checks and prints every step. No step writes a shell profile; the one profile edit
  on offer (`uv tool update-shell`) is asked for separately. Installers inherit the terminal, so a
  password prompt goes straight from the official installer to the user.
- **No credentials.** Sign-in is checked with each CLI's own status command (`claude auth status`,
  `codex login status`). Only the exit code and a `loggedIn` boolean are used; the output is never
  printed, logged or stored. The user signs in by running the named command in their own terminal.
- **Scripts.** `install/install.sh` is bash 3.2 compatible (no associative arrays, `mapfile`,
  `${x,,}`, `|&` or `&>>`). `install/install.ps1` is ASCII only with CRLF, runs on Windows
  PowerShell 5.1 and PowerShell 7, never passes embedded double quotes to native programs, and
  refreshes `$env:Path` from the registry after each install.
- **Exit codes and tokens.**
  - `python -m oah.setup`: 0 when every required tool is ready, 1 otherwise, 2 usage. Last line
    `SETUP_OK`, `SETUP_INCOMPLETE missing=<names>` or `SETUP_DRY_RUN planned=<n>`.
  - Installers: 0 with `OAH_INSTALL_OK` or `OAH_INSTALL_DRY_RUN_OK`; 1 with `OAH_INSTALL_INCOMPLETE`
    (oah installed, doctor reports a required tool missing) or `OAH_INSTALL_FAILED`; 2 with
    `OAH_INSTALL_USAGE`.
  - `oah doctor`: exit 1 only when a required tool (git, python, claude, codex) is not usable. Not
    installed, too old, unable to run, a refused batch shim and not signed in all count as not usable,
    as P1 already did for Codex.

## Review Focus

1. **A consent bypass.** Any path where an install command runs without `y`/`--yes`, or during a dry
   run. → `test_run_installs_skips_declined_steps`, `test_dry_run_never_calls_runner`,
   `test_install_sh_dry_run_changes_nothing`, `test_install_ps1_dry_run_changes_nothing` (Windows).
2. **Argument injection.** The runner resolves the program through `oah.engines.proc`, passes argv
   literally and never launches `.cmd`/`.bat`. → `test_default_runner_passes_argv_literally`,
   `test_default_runner_refuses_batch_files`.
3. **Credential exposure.** Status output containing an account identifier never reaches the screen.
   → `test_sign_in_never_prints_status_output`.
4. **Catalog drift.** The shell scripts' bootstrap uv command equals the catalog's, and every entry
   has a check, an install per OS (or a manual URL) and an https URL. → `test_catalog_is_complete`,
   `test_install_scripts_use_catalog_uv_command`.
5. **PowerShell 5.1.** The script is ASCII + CRLF and its dry run passes on both shells (CI).

### Task 1: The tool catalog

**Files:**
- Create: `src/oah/setup/__init__.py`, `src/oah/setup/tools.py`, `tests/test_setup.py`

**Interfaces:**
- `Tool(name, required: bool, purpose, check: tuple[str, ...], version_args, install:
  Mapping[os_name, tuple[argv, ...]], url, os_url={}, min_version=None, detect="path", sign_in=None,
  note="")`. `os_name` is `"macos"` or `"windows"`. `install` alternatives are in preference order;
  the first whose program exists is used. `detect` is `path`, `python` (the running interpreter) or
  `unlazy` (`oah.unlazy.find_unlazy_dir`). `Tool.url_for(os_name)`.
- `SignIn(status_args, login)`: claude `("auth", "status")` / `claude auth login`; codex
  `("login", "status")` / `codex login`.
- `catalog() -> list[Tool]` in display order: git, python, uv, node, claude, codex, unlazy, graphify,
  gh, gitleaks, jq, rg. Required: git, python, claude, codex.
- `sh(text)`, `powershell(text)`, `display(argv)`, `needs(argv)`: `needs` is the program that must
  exist, which is the first word of a wrapped one-liner's text (`irm` needs nothing beyond PowerShell).
- `os_name_for(platform) -> str`.

### Task 2: Check, plan, run

**Files:**

**Interfaces:**
- `check_tools(tools, *, which=shutil.which, env=None, home=None, repo_root=None) -> list[ToolStatus]`;

- `plan_installs(statuses, *, os_name, which=shutil.which) -> list[Step]`; `Step(tool, argv | None,

  terminal and refuses batch files.
- `refresh_path(env=os.environ, *, platform=sys.platform, read_registry=...)`: Windows merges the
  machine and user `Path` from the registry; POSIX adds `~/.local/bin` when it exists.

## Coordinator note 2 (2026-10-23)

- **Node is required only when gates are used** (PLAN 5.13). `oah doctor` finds the project (the git
  top level, or without git the nearest folder upwards holding `.oah` or `.git`). Node counts as
  required when that project has any `.oah/tasks/*/GATES.md`, or a `[gates]` table in
  `.oah/config.toml` that does not say `enabled = false`. Otherwise it is recommended. The catalog
  marks it with `required_for_gates`. Tests: `test_node_required_when_tasks_have_gate_ledgers`,
  `test_node_required_when_config_enables_gates`, `test_node_recommended_without_a_project`,
  `test_gates_in_use_table`, `test_project_root_walks_up_to_oah_or_git`, and in `tests/test_cli.py`
  `test_doctor_counts_node_as_required_when_the_project_uses_gates` /
  `test_doctor_counts_node_as_recommended_without_gates`.
- **Deviation from PLAN 6.1: `brew install node`, not `brew install node@24`.** Homebrew's versioned
  `node@24` formula is keg-only, so `node` stays off PATH after the install and the setup's re-check
  still reports it missing. The linked `node` formula lands on PATH; it installs the current Node
  release, far above unlazy's Node 16 minimum.
- **Piped bootstrap (spec delta, PLAN 6.5 step 1).** Both scripts also run piped
  (`curl <url> | bash`, `irm <url> | iex`). When they are not inside a clone, they download the pinned
  release archive, verify its SHA-256 against the release digest before extracting, and continue
  from the extracted folder; git is not needed (step 2 offers it with consent). The release URL and
  digest are placeholders at the top of each script until the owner publishes; a placeholder refuses
  with `OAH_INSTALL_NOT_PUBLISHED`. Tests override them with `OAH_RELEASE_URL` / `OAH_RELEASE_SHA256`
  pointing at a local fake archive. The end checks that `oah` resolves in a fresh shell and hands over
  to `oah init`.
