# P7c CI Starter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oah ci init` writes a starter GitHub Actions workflow, `.github/workflows/oah-ci.yml`, for the
user's own project: tests on the OSes they pick, plus a pinned gitleaks scan. It shows the file in full
and writes only after the user confirms (A21). Guided `oah init` (lane P7b) reuses the same API.

**Architecture:**
- **`oah.ci` package** (`src/oah/ci/`): `detect.py` finds test commands, `workflow.py` renders the
  template, builds a `CiPlan` and writes it. `__init__.py` re-exports the API.
- **Templates** (`src/oah/templates/ci/`): one workflow template with `@@NAME@@` markers, plus one YAML
  snippet per setup step and the placeholder step. Markers are replaced with `str.replace`, so GitHub's
  `${{ … }}` expressions need no escaping; a leftover `@@` is a programming error.
- **Command module** `src/oah/ci_cli.py`: `COMMANDS = ("ci",)` with one action, `init`. It does the
  prompting; the core never reads stdin or config.

**Tech Stack:** Python 3.11+ stdlib (`tomllib`, `json`, `difflib`, `importlib.resources`, `argparse`,
`unittest`), git through `oah.paths`.

**Spec:** `docs/PLAN.md` (3, 5.3, 6.5, 7, 8, A17) and amendment 5 (A21, plan PR #20); the lane intent
in the dispatch brief is authoritative.

## Global Constraints

- Everything from the earlier plans' Global Constraints still applies: stdlib only, never
  `shell=True`, UTF-8 on every read and write, parsers accept CRLF, a Korean one-line header on new
  `.py` files, test writes inside the checkout.
- **Consent.** Nothing is written without an explicit `y` or `--yes`. `--dry-run` writes nothing and
  asks nothing. An existing file is replaced only after its unified diff is shown and the user answers
  `y`, or with `--force --yes`. End of input counts as "no".
- **Pins.** Every `uses:` names a full 40-hex commit SHA and a `# vX.Y.Z` comment. The SHAs were read
  with `git ls-remote` against each action's official repository on 2026-10-23 (all four tags are
  lightweight, so the tag SHA is the commit):
  - `actions/checkout` v7.0.1 `3d3c42e5aac5ba805825da76410c181273ba90b1` (same as this repository);
  - `actions/setup-python` v7.0.0 `5fda3b95a4ea91299a34e894583c3862153e4b97` (same as this repository);
  - `actions/setup-node` v7.1.0 `949feb2413d6458794dcd2491c4babbbce0c15c1`;
  - `actions/setup-go` v7.0.0 `b7ad1dad31e06c5925ef5d2fc7ad053ef454303e`.
  - Rust needs no action: GitHub's hosted runners ship rustup and cargo.
- **gitleaks** reuses `.github/workflows/secrets.yml`: version 8.30.1, archive SHA-256
  `551f6fc8…f2470eb`, checked with `sha256sum -c` before extraction. It runs
  `gitleaks detect --source . --redact --no-banner` after a `fetch-depth: 0` checkout, without verbose
  output or reports: redaction alone does not hide adjacent values in finding context.
  Flags verified against the [8.30.1 documentation](https://github.com/gitleaks/gitleaks/blob/v8.30.1/README.md#usage).
- **A17.** The workflow holds no secret, no token, no `secrets.` reference and no repository setting
  change. `actions/checkout` runs with `persist-credentials: false`. A typed test command may not
  contain `${{`, so it cannot pull a secret in.
- **Shell.** The test job sets `defaults.run.shell: bash` (bash exists on every hosted runner, Git Bash
  on Windows), and each command is its own step, so a failing command always fails its step.
- **Errors** are `CiError(code, message)` and start with an `OAH_CI_*` code. Exit codes: 0 ok (including
  dry run and "already up to date"), 1 refused (declined, ambiguous with `--yes`, existing file with
  `--yes` but no `--force`, file changed since shown), 2 usage (bad `--os`, bad `--test-command`),
  69 environment (not a repository, config errors, unreadable target, storage errors).

## Interfaces

- `oah.ci.WORKFLOW_PATH = PurePosixPath(".github/workflows/oah-ci.yml")`.
- `oah.ci.DEFAULTS = {"os": [], "test_command": ""}`; the CLI reads `load_config(root).section("ci", DEFAULTS)`.
- `oah.ci.RUNNERS = {"macos": "macos-latest", "windows": "windows-latest", "linux": "ubuntu-latest"}`.
- `oah.ci.current_os(platform: str = sys.platform) -> str`.
- `oah.ci.parse_oses(values: Iterable[str]) -> tuple[str, ...]`: lower-cased, de-duplicated, in the
  given order; `OAH_CI_OS_INVALID` for anything else or an empty list.
- `oah.ci.Step(name: str, run: str)` and `oah.ci.Detection(ecosystem, label, reason, steps, setup)`.
- `oah.ci.detect(root: Path) -> tuple[Detection, ...]`, in the order Python, Node, Go, Rust:
  - **Python** when `pyproject.toml` or `setup.cfg` exists, or `tests/` holds a `.py` file. pytest is
    configured by `pytest.ini`, a root or `tests/` `conftest.py`, `[tool.pytest.ini_options]` in
    `pyproject.toml`, `[tool:pytest]` in `setup.cfg`, or a `pytest` requirement in the project's
    dependencies, optional dependencies, dependency groups or `requirements*.txt`. Steps: install
    `requirements.txt` when present, `python -m pip install -e .` when `pyproject.toml` has `[project]`,
    then `python -m pip install pytest` and `python -m pytest`. Without pytest, `test*.py` files directly
    in `tests/` use `python -m unittest discover -s tests` (no `__init__.py` needed); root-level
    `test*.py` files use `python -m unittest discover`. Filenames must be valid Python module names.
    No supported test layout means no Python
    detection, so the failing placeholder is used when no other ecosystem is detected.
  - **Node** when `package.json` has a non-empty `scripts.test`: `npm ci`, then `npm test`.
  - **Go** when `go.mod` exists: `go test ./...`. **Rust** when `Cargo.toml` exists: `cargo test`.
  - Unparseable files never raise; they just do not count as configuration.
- `oah.ci.CiPlan` (frozen): `root`, `path`, `oses`, `detection` (or `None`), `steps`, `placeholder`,
  `text` (the rendered file, LF), `existing` (current file text or `None`); `diff` (unified diff,
  `""` for a new file) and `up_to_date`.
- `oah.ci.plan(root, oses=None, test_command=None) -> CiPlan`:
  - `oses` empty or `None` → the current OS.
  - `test_command` `None` → the only detection, the placeholder when there is none, and
    `OAH_CI_AMBIGUOUS` when there are several. A `Detection` → that one. A `str` → one "Run tests" step,
    with the setup steps of every detected ecosystem. `OAH_CI_TEST_COMMAND_INVALID` for an empty
    command, a line break or control character, or `${{`.
  - `OAH_CI_TARGET_INVALID` when the target is a symlink, not a file, outside the root, or not UTF-8.
- `oah.ci.write(plan, *, confirm: bool, overwrite: bool = False) -> Path`:
  - `OAH_CI_NOT_CONFIRMED` unless `confirm`; `OAH_CI_CHANGED` when the file on disk differs from
    `plan.existing`; `OAH_CI_EXISTS` when a file exists and not `overwrite`.
  - Writes with `oah.atomic.write_text_atomic`, keeping CRLF when the replaced file used CRLF.
- `oah ci init [--os LIST] [--test-command CMD] [--dry-run] [--yes] [--force]`. Precedence: flag, then
  `[ci]` config, then detection.

## Review Focus

1. **A write without consent.** → `test_dry_run_writes_nothing`, `test_declined_writes_nothing`,
   `test_end_of_input_writes_nothing`, `test_write_requires_confirm`.
2. **A silent overwrite.** → `test_existing_file_shows_diff_and_asks`, `test_yes_without_force_refuses`,
   `test_write_refuses_file_changed_since_plan`.
3. **An unpinned or mis-pinned action, or a gitleaks pin that drifts from this repository's.** →
   `test_every_uses_is_pinned_to_a_full_sha`, `test_gitleaks_pin_matches_repository_secret_scan`.
4. **A secret or token in the template, or YAML broken by a typed command.** →
   `test_no_secret_or_token_in_workflow`, `test_typed_command_is_literal`,
   `test_test_command_rejects_line_breaks_and_expressions`.
5. **False detection** (a Node project's `tests/` folder read as Python). →
   `test_tests_folder_without_python_files_is_not_python`.
