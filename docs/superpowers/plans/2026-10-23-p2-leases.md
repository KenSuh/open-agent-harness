# P2 State and Leases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shared, crash-safe leases, so that sessions and worktrees of one repository never edit
overlapping paths at the same time. The commands are `oah start`, `renew`, `status`, `finish`,
`release` and `log`.

**Architecture:**
- **Where state lives:** in `<git common dir>/oah/` (or `OAH_STATE_DIR`), so every worktree sees it.
- **Writes:** every mutation takes one OS file lock (`fcntl.flock` on macOS, `msvcrt.locking` on
  Windows) and replaces JSON atomically (temp file → fsync → `os.replace`).
- **Reads:** reads take no lock and create nothing.
- **Scope:** checked against real changes at `finish`.

**Tech Stack:** Python 3.11+ stdlib (`fcntl`/`msvcrt`, `os.replace`, `multiprocessing`, `unittest`),
git through `oah.engines.proc`.

**Spec:** `docs/PLAN.md` (5.1, 5.4, 5.13, 8, 11, 15)

## Global Constraints

- Everything from the P1 plan's Global Constraints still applies: stdlib only, never `shell=True`,
  UTF-8 everywhere, a Korean one-line header on new `.py` files, test writes inside the checkout.
- **State location:** `git rev-parse --git-common-dir` + `/oah/`, or `OAH_STATE_DIR` when set. It
  contains `.lock`, `leases.json`, `events.jsonl` and a pending `transaction.json` during publication.
- **Read-only commands create nothing.** `oah status` creates no folder or file, takes no lock, and
  reports a missing state as empty.
- **Locking:**
  - Mutations hold the single state lock for one short critical section.
  - The lock waits up to 10 s, then fails with `OAH_STATE_LOCK_TIMEOUT`. A lock never outlives its
    process, because the OS releases it on exit.
- **Atomic writes:**
  - A temp file goes in the same folder and is flushed and fsynced.
  - `os.replace` is retried on `PermissionError` for up to 2 s on Windows.
  - The parent folder is fsynced on POSIX.
  - A corrupt `leases.json` fails with `OAH_STATE_CORRUPT`. It is never reset silently.
  - Mutations durably write their state and event to the transaction journal before publishing either.
    The next mutation replays an interrupted transaction under the lock, without duplicating its event.
    Recovery validates the live lease file and replacement state, then durably republishes the journal
    before publishing state. A corrupt live file preserves both files untouched. Read-only commands
    report `OAH_STATE_PENDING` without recovering or writing anything.
  - Storage `OSError`s report `OAH_STATE_IO`, name the failed path, and exit 69.
- **Lease record:** `{id, task, agent, scope[], note, worktree, branch, head_at_start, created_at, expires_at}`.
  - Times are UTC ISO-8601 and the default TTL is 4 h.
  - `task` matches `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`, and `agent` matches `[A-Za-z0-9._-]{1,32}`.
- **Scope:**
  - User input is `repo`, or paths resolved relative to the repository: separators become `/`, `.`
    and `..` follow the host OS's resolution rules, and escape is refused (`OAH_SCOPE_INVALID`).
    Windows collapses `link/..` lexically before following an alias; POSIX follows the link first.
    Drive-relative input (`c:x`, `C:`, `c:src/a.py`) is refused before resolution on every OS.
    Other input that is not absolute on the host OS refuses colons after any drive before resolution.
    Host-absolute input checks colons in the resolved repository-relative path, allowing a POSIX
    repository root containing `:` while still refusing NTFS streams. Absolute and UNC paths still
    undergo the repository containment check.
  - The acquired canonical scope stays fixed until an explicit, conflict-checked scope renewal.
    `outside(scope, changed, *, root=None)` first compares it with Git entries literally, folding only
    case and NFC for comparison. With a root, an entry whose literal path is not covered matches only
    when its resolved parent is inside the resolved root, the resulting relative path (final component
    kept literal) is covered, and that path also occurs in `changed` under the same case and NFC folding.
    Thus a tracked junction edit with its canonical twin passes; entries reported only through a swapped
    folder require the recorded `--allow-out-of-scope` override. `Store.finish` supplies the lease's
    recorded worktree. Missing parents, loops and OS errors disable only this second test; changed
    entries never raise `OAH_SCOPE_INVALID`. It checks `repo`
    before reading or resolving entries, never replaces their backslashes or rejects their colons,
    and never re-normalizes the acquired scope. A deleted `src/a.py` and a replacement symlink or
    junction `src` both remain in `src` through the literal test.
  - An empty scope is refused (`OAH_SCOPE_EMPTY`, PLAN A4), so `--scope` is required.
  - Two scopes overlap when either is `repo`, or one path equals the other or is a component prefix
    of it. `src` overlaps `src/a.py`; `src` does not overlap `srcx`.
- **Exit codes:**
  - 0: success;
  - 1: refused (the `OAH_*` code is printed first on stderr);
  - 2: usage;
  - 69: environment (not a git repository, git missing, lock timeout, corrupt state).
- **Events** are one JSON object per line in `events.jsonl`: `{ts, event, task, agent, lease_id, ...}`.
  The event types are `lease_started`, `lease_renewed`, `lease_finished`, `lease_released`,
  `lease_expired` and `note`.

## Review Focus

1. **Two sessions start overlapping leases at the same moment.** Exactly one wins and the other is
   refused, with no lost update. → Task 4 `test_concurrent_overlapping_starts_admit_exactly_one`.
2. **A reader runs while a writer replaces the file**, especially on Windows, where an open handle
   blocks `os.replace`. The reader always sees valid JSON and the writer retries.
   → Task 2 `test_replace_retries_while_reader_holds_file` (Windows), `test_concurrent_reader_never_sees_partial_json`.
3. **A leaseholder's process crashes while holding the lock.** The next command proceeds. → Task 1
   `test_lock_is_released_when_holder_process_dies`.
4. **Scope given as `src\a.py`, `./src/../src/a.py`, `SRC` or an absolute path inside the repo.** These
   normalize to the same key, and a path outside the repo is refused. → Task 3 `test_scope_normalization_table`.
5. **`oah status` run in a fresh clone or a second worktree.** It creates nothing, and the second
   worktree sees the first one's leases. → Task 5 `test_status_creates_nothing`,
   `test_second_worktree_sees_leases`.

### Task 4: Lease store operations

**Files:**
- Create: `src/oah/lease.py`, `tests/test_lease.py`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces:
  - `@dataclass Lease` with the fields from Global Constraints, plus `to_json()` / `from_json()`.
  - `LeaseError(code: str, message: str)`. The codes are `OAH_LEASE_CONFLICT`, `OAH_LEASE_EXISTS`,
    `OAH_LEASE_NOT_FOUND`, `OAH_LEASE_NOT_YOURS`, `OAH_LEASE_EXPIRED`, `OAH_SCOPE_EXCEEDED` and
    `OAH_TASK_INVALID`.
  - `Store(state_dir: Path, *, now: Callable[[], datetime] = utc_now)` with these methods:
    - `start(task, agent, scope, note, ttl_hours, info) -> Lease`;
    - `renew(task, agent, ttl_hours, scope=None) -> Lease`;
    - `finish(task, agent, summary, changed, allow_out_of_scope) -> Lease`;
    - `release(task, agent, reason, force) -> Lease`;
    - `log(task, agent, message) -> None`;
    - `snapshot() -> list[tuple[Lease, bool]]`, where the flag means stale. It is read-only.
- Rules:
  - `start` prunes expired leases first, each logged as `lease_expired`.
  - The same task under the same agent is refused with `OAH_LEASE_EXISTS` (use `renew`). The same
    task under another agent is refused with `OAH_LEASE_CONFLICT`.
  - An overlapping lease of another task is refused with `OAH_LEASE_CONFLICT`. The message names the
    holder's task, agent, scope and expiry.
  - `renew` on an expired lease is refused with `OAH_LEASE_EXPIRED`.
  - `release` by another agent needs `force=True`, and is recorded as forced.
  - `finish` refuses `OAH_SCOPE_EXCEEDED` (listing the files) unless `allow_out_of_scope`, which is
    recorded in the event.
