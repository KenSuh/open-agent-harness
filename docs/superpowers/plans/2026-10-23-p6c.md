# P6c Review Summary and Landing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oah review summary --task T` prints a PR-ready block from the task's receipts. `oah land --check --task T`
proves, immediately before landing, that review, gates, the secret scan and CI bind to the exact task head, and that a
freshly fetched default branch adds no unmet checks. `oah land --merge` repeats that check, asks, and fast-forwards the
remote default branch to that head under a remote-enforced lease on the fetched SHA.

**Architecture:**
- `oah.review.summary` reads the evidence of a task and renders the block.
  - Receipts come from `oah.review.receipts`.
  - Convergence comes from `oah.review.rounds.gate`, the one convergence predicate that `oah review` also uses.
  - The task's latest lease comes from the active lease, else `events.jsonl`.
  - Gates come from `GATES.summary.md` as committed at a revision.
- `oah.land` runs the landing checks in one fixed order (table below) and does the conditional push.
  `oah.land_cli` owns arguments, confirmation, output and exit codes.
- Impact reuses P7i/P7j: `mapstore.fresh_map` (worktree map), `defaultbranch._query_context` (a fetch into the
  private mirror; the user's refs are never written), `query.merge_maps`. Gate definitions are read from committed
  ledgers at both pinned revisions, HEAD from the user's repository and the fetched SHA from the mirror.

**Tech Stack:** Python 3.11+ stdlib (`argparse`, `string.Template`, `json`, `unittest`), git, `gh` and `gitleaks`
through `oah.paths.git_argv` and `oah.engines.proc`.

**Spec:** `docs/PLAN.md` 5.9 (review summary, Landing, the reviewer binary), 5.10 (A11, both maps), section 4 row 29,
A11, A17, A23, and the section 15 P6 items naming `review summary` or `land`; lane intent `p6c` revision 1.

## Global Constraints

- Python 3.11+, stdlib only; macOS 13+ and native Windows 11 (no WSL); never `shell=True`; UTF-8 on every read and
  write; parsers accept CRLF; a Korean one-line header on every new `.py` file.
- Nothing irreversible without explicit confirmation: `--merge` pushes only after an interactive yes or
  `--confirm <full head SHA>`. Global files are never written.
- A17: no token, password, cookie or account identifier reaches output, records or exceptions. oah never reads
  credentials. `gh` and git use their own helpers. Remote URLs, `gh` stderr, `git push` stderr and gitleaks
  findings are never echoed or stored. `gh` receives an explicit private destination selector and API host,
  overriding inherited `GH_REPO`, `GH_HOST` and its configured default; identifiers never enter output or records.
- Exit codes are 0 for ready or landed, 1 for refused, 2 for usage, and 69 for environment problems (not a
  repository, git missing, config, state, lock).
- Untouched: `oah review --task T` behaves exactly as landed, and `[review] critical_paths` stays in
  `oah.review.settings.DEFAULTS` as landed (P6a already added it with the intent's defaults). P6b's files are not
  edited. Landing needs no new config keys: it reads `[impact]`, `[gates]` and `[review]`.
- Records go to `<state>/land/<task>/records.jsonl`, one JSON line per run under the state lock. They hold SHAs,
  digests, fixed landing-check names, states and codes. They never hold messages, CI names, paths or URLs.
- **C3 output boundary (owner invariant E).** Gate, tool, impact and CLI exceptions map to fixed diagnostics;
  record-write warnings never include exception text. Repository names remain internal for evidence matching and
  push. Text, JSON and records identify task names, remote names, branch names and paths only by one-based position
  and SHA-256 digest (or omit them in fixed instructions). Required checks retain their definition digest and
  generated binding/state enums; gate labels are included only when the entire label matches
  `[A-Za-z0-9._#:-]{1,80}`. This exception never permits target paths or destination names. The same projection is
  used for required-check messages, JSON and records, including passing checks; handoff labels follow the same
  rule. Impact warnings become fixed warnings, review refusals use a fixed next step, and confirmation errors
  never echo the supplied value. Landed evidence predicates and `oah review`/`review summary` remain unchanged.

## Landing checks (one place: `oah.land.assess`)

Precondition: HEAD exists, the caller is not a dispatched worker (`OAH_LAND_WORKER_REFUSED`), tracked files are
clean, and no untracked file outside the generated gate outputs exists (`OAH_LAND_DIRTY_TREE`). Gate input manifests
hash untracked files, so evidence could otherwise depend on a file that never lands. Every check reports `passed`, `failed`, `unverified` or `skipped`. A check is
`skipped` when a check it needs failed. The run is ready only when every check is `passed`, or `unverified` for
CI. The headline is the first failure in this order.

| # | check | passes when | failure codes |
|---|---|---|---|
| 1 | lease | no lease, active or stale, is recorded for this worktree (the pre-push hook would refuse) | `OAH_LAND_LEASE_OPEN` |
| 2 | intent | the task's latest lease binding is `current`, and its packet is committed at HEAD as bound | `OAH_LAND_INTENT_NOT_CURRENT` |
| 3 | review | `rounds.gate(...)` returns `converged` for HEAD and that binding, with the series base taken from the task's latest receipt | `OAH_LAND_REVIEW_REQUIRED` |
| 4 | gates | a ledger governs the task; `guard.evaluate` passes with unlazy; its summary text equals `GATES.summary.md` committed at HEAD (with `commit_ledgers`, each ledger is committed at HEAD byte for byte) | `OAH_LAND_GATES_REQUIRED`, `OAH_LAND_GATES_UNMET`, `OAH_LAND_GATES_SUMMARY_MISSING`, `OAH_LAND_GATES_SUMMARY_STALE` |
| 5 | impact | the worktree map is fresh at HEAD; the default branch was fetched in this run; the changed paths are assessed against both maps; the result digest is recorded | `OAH_LAND_IMPACT_STALE` |
| 6 | required-checks | every newly affected check (below) has passing evidence against HEAD | `OAH_LAND_CHECKS_REQUIRED` |
| 7 | fast-forward | HEAD contains the fetched SHA F and differs from it | `OAH_LAND_IMPACT_STALE` (the branch moved), `OAH_LAND_NOTHING_TO_LAND` |
| 8 | scan | gitleaks reports nothing in `F..HEAD` (`--redact`, output never echoed) | `OAH_LAND_SCAN_REQUIRED` (no gitleaks), `OAH_LAND_SCAN_FAILED` |
| 9 | ci | with `gh` explicitly bound to the destination, every page was read completely and every check run for HEAD completed as success, neutral or skipped. Only absent `gh` or zero check runs is `unverified`; all read errors refuse, preserving known failures | `OAH_LAND_CI_FAILED`, `OAH_LAND_CI_PENDING` |

- **Changed paths.** When HEAD contains F, they are `F..HEAD`, exactly what lands. Otherwise they are the review
  range `context.resolve(root, None, ...)` from the merge-base with the local default ref to HEAD.
- **Newly affected checks.** These are gate rows with binding pin or exec on a changed path, taken from the ledgers
  committed at F, discovered with the impact settings committed at F. The fetched map is rebuilt with those settings;
  changing HEAD's ledger globs cannot remove fetched requirements. A definition already committed at HEAD still
  requires passing execution evidence.
  - A check *passes* when one of the task's governing ledgers has a gate with the same definition digest (CHECK,
    EXPECT, CWD) that unlazy reports met and whose binding is fresh (`guard.assess(...).fresh == "fresh"`).
  - It *failed* when such a gate exists but is not fresh and met.
  - It is *pending* otherwise.
  - CI workflow bindings are left to the CI check runs of the exact head.
- **Destination (C1).** Accept one literal fetch URL and zero or one byte-identical push URL. Refuse multiple
  destinations and all `insteadOf`/`pushInsteadOf` configuration, including local/global and inherited command
  configuration: isolated fetch and checkout push otherwise interpret these differently. Pin the private literal
  destination, compare the fetched mirror's source digest, recheck it after confirmation, and push to that literal
  destination. Only digests may be persisted; URLs and repository identifiers stay private. Relative local URLs are
  resolved from the checkout. CI explicitly selects this destination and API host rather than gh's default or
  inherited repository. Local bare URLs use a digest-only invalid selector that fake gh understands; real gh refuses before a request.
  Unsupported transports and nonstandard service ports cannot supply passing GitHub CI evidence.
- **Merge (C1).** After confirmation, acquire the existing state lock, revalidate clean HEAD, lease, intent, latest
  review, governing gates and affected fetched definitions, and compare the authorization state digest captured
  during assessment. A change refuses and requires a fresh assessment and confirmation. Hold the lock through push
  so cooperating lease, review and gate binding writers cannot supersede validation. Read-only landed APIs take no
  nested state lock; landing records are written after releasing it. Arbitrary editors remain outside this protocol.
  Push with `git push --porcelain --no-follow-tags --force-with-lease=refs/heads/<branch>:<F> <verified-destination>
  <HEAD>:refs/heads/<branch>`; the remote updates the branch only while it still equals F.
  Automatic tag following is disabled even with `push.followTags=true`; confirmation covers only the branch ref.
  - After a failed push, freshly fetch and verify the same destination and branch, keeping the mirror generation
    leased while reading its history. HEAD in that history counts as landed, including a subsequent descendant.
  - Complete history excluding HEAD proves nothing landed: a moved branch is `OAH_LAND_IMPACT_STALE`; one still at
    F is `OAH_LAND_PUSH_FAILED`. Failed identity/history verification or incomplete history gives
    `OAH_LAND_OUTCOME_UNCERTAIN`, with `landed: null` in output and records; inspect the destination before retrying.
  - Push reasons are fixed allowlisted diagnostics. Neither porcelain rejection reasons nor `OAH_` hook stderr
    are trusted or exported. Literal pushes disable Git/curl/trace2 tracing so URLs cannot enter trace logs.
  - CI pagination remains bounded at ten pages. A response known to be incomplete refuses with
    `OAH_LAND_CI_PENDING`; it can never produce passed or ready from the first 1,000 runs alone. HTTP errors,
    timeouts, malformed pages, mismatched heads, invalid enums or inconsistent/incomplete totals also refuse.
    Already observed failures take precedence (`OAH_LAND_CI_FAILED`) over an incomplete read.
  - CI names and all other external response strings are discarded. Status and conclusion must be fixed enums;
    failed and pending runs are reported only by count and one-based position, in text and JSON. Records keep codes.
  - Confirmation codes: `OAH_LAND_CONFIRM_REQUIRED` (non-interactive without `--confirm`), `OAH_LAND_CONFIRM_MISMATCH`
    and `OAH_LAND_CANCELLED`.

## Review Focus

- The gate-summary digest hashes the exact committed blob bytes read through `git cat-file blob`, including any
  committed CRLF. Working-tree newline translation and `core.autocrlf` cannot change that identity. Fixtures use
  byte writes; digest expectations read the committed blob in binary mode.

- A finding title with `@name` or backticks pasted into a PR body must not mention anyone or break the table:
  titles and locations are rendered inside safe code spans; land discards CI check names entirely
  (`test_summary_quotes_untrusted_text`, Task 2).
- A receipt's `reviewer.cli_path` holds an absolute home path; the summary and its JSON never print it
  (`test_summary_omits_reviewer_path`, Task 2).
- `gh` that prints a token-like string, `html_url` or an owner login, and a remote whose path is personal, never
  reach land output or records (`test_land_output_and_records_hold_no_credentials`, Task 5).
- C3 regressions exercise real gate runtime failures and unavailable/unpinned tools, invalid configuration and
  record I/O failures, private required-gate/target paths and destination names, exact gate-label boundaries
  (including Windows paths, Unicode, overlong labels and final newlines), and a successful push after a private
  confirmation mismatch. Repositories and bare remotes are local; existing tool process fixtures are reused.
- C4 assembles Windows home-path fixtures at runtime, preserving private label/target digest coverage without
  committing home-path literals. A regression scans the test source with the real repository privacy rules.
- `oah review` without `--task`, and `oah review --task T` with every landed option, keep their landed behaviour once
  `summary` exists (`test_review_still_requires_task_and_runs_rounds`, Task 2).
- A newer converged receipt for another head, or a round started after convergence, must never let an older approval
  land (`test_review_check_uses_latest_task_event`, Task 3).
