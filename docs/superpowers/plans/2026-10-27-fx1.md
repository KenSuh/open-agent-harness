## Task 1: Atomic PID files in the fake Orca (AC1)

**Files:** `tests/fakes/fake_orca.py`, `tests/test_launcher_orca.py`

Interfaces in `fake_orca.py`:
- `publish_pid(path: pathlib.Path, pid: int) -> None`: writes `f"{pid}\n"` to a unique temporary file
  in the same folder, then `os.replace`s it onto `path`. Every PID file write (host start, host
  launch failure, `FAKE_ORCA_HOLD`) goes through it.
- `read_pid(path: pathlib.Path) -> int | None`: the integer when the file holds a complete record
  (`^\d+\n$`), otherwise `None` (missing, empty or partial).
- `terminal_create` waits until `read_pid` returns an integer instead of waiting for existence.

Tests (`FakeOrcaPidFileTest` in `tests/test_launcher_orca.py`):
- `test_publish_never_opens_the_final_path_for_writing`: a child Python process with an audit hook
  calls `publish_pid` and reports every file opened for writing; the final path is never one of them.
- `test_concurrent_reader_never_sees_a_partial_pid`: a reader thread polls fresh PID paths while a
  writer publishes PIDs of varying lengths; every read of an existing file is a complete record.
- `test_reader_waits_for_a_complete_integer`: `read_pid` returns `None` for an empty file and for
  digits without the newline terminator, and the integer once published.

## Task 3: Email rule ignores backslash escapes (AC3)

**Files:** `tools/privacy_scan.py`, `tests/test_privacy_scan.py`

`EMAIL` captures the consecutive backslashes in group 1 and the full address in group 2. `scan_text`
skips an initial `abfnrtv` escape letter only after an odd number of backslashes. An even number
represents literal backslashes and preserves the complete local part. If removing an escape letter
would create an allowlisted mailbox, retain and report the original address: ambiguous text must
not hide a private address. A backslash before any other letter keeps the whole address.

Tests (`PrivacyScanTest`):
- `test_email_after_backslash_escape_is_not_an_address`: `\n`, `\r\n`, `\t` and odd runs of
  backslashes followed by an escape letter directly before `@<file>.md` give no finding.
- `test_literal_backslashes_preserve_real_email_local_parts`: byte-exact JSON strings with one,
  two or three escaped backslash pairs preserve both single-letter and longer local parts, including
  names that would become allowlisted if their initial letter were dropped. The doubled-backslash
  fixture before `n@<file>.md` is an address and must be reported.
- `test_escape_trimming_cannot_create_an_allowed_mailbox`: odd backslashes cannot hide a private
  mailbox through trimming; an escape prefix also cannot disguise a private address as an allowed one.
- `test_json_email_fixture_is_reported_without_allowlist_collision`: a real temporary Git repository
  with byte-exact JSON fixtures reports all three addresses and redacts their values in CLI output.
- `test_real_emails_next_to_punctuation_and_escapes_are_found`: addresses in parentheses, angle and
  square brackets, quotes, followed by `.`/`,`/`;`, and after `\n` or `\t` are all reported, with the
  escape letter excluded from the value. A one-letter local part after a non-escape backslash (`\z`)
  keeps its letter, and an address whose first letter reads as an escape is still reported.

## Correction C1: Deterministic running-status assertion

`test_wait_returns_75_while_running_then_the_final_record` replaces `FAKE_SLEEP="4"` with
`FAKE_ORCA_RELEASE`, a file path read by a waiting process in the fake Orca terminal. Its PID is
published normally, but the actual worker starts only after the test writes the release file. The
test releases it after asserting the running status and the absence of an engine record. A cleanup
also releases it before stopping the host if an assertion fails. Existing wait limits stay unchanged;
the handshake uses only files and Python subprocesses on macOS and native Windows.

C1 verification: the three new privacy regressions and the release-gated launcher test failed before
their fixes. All five focused privacy tests (escape-only, literal backslashes, allowlist collisions,
JSON repository fixture, punctuation/escapes) and the launcher test each passed 30 consecutive runs
on Python 3.11.15 and Python 3.14.4: 180/180 test executions per interpreter. Windows execution was
unavailable; fixtures use explicit bytes, and the release handshake uses argv lists without a shell.

Both requested full discovery runs completed with 2,097 tests and 93 skips each. Python 3.11.15
reported 22 errors and no assertion failures; Python 3.14.4 reported the same 22 errors plus one
failure. All 22 errors originate in `tests/test_rerank.py`: the sandbox denies binding its fake HTTP
server to localhost (`PermissionError`). The additional 3.14 failure is
`tests.test_packaging.PackagingTest.test_wheel_ships_templates`: its isolated pip build cannot fetch
`setuptools>=77` from PyPI offline. These checks remain unverified in this environment; no refusals,
test limits or out-of-scope files were changed to bypass them.

## Correction C2: Explicit launcher schedules

- Finding 1: contributors get deterministic terminal-log collection. A one-shot `Orca.json` hook
  releases the blocked worker only after the follower has read its running record and entered
  `terminal wait`. Separate real-process regressions force completion before the terminal-wait RPC
  (output must be collected) and completion before the follower starts (the finished record is
  returned without Orca calls or a terminal log).
- Finding 2: contributors exercise the environment allowlist on actual follower invocations. The
  environment test holds the host until terminal wait, and checks wait/read/show explicitly. A
  separate late-follower schedule finishes the worker first and proves that only the three launch
  invocations need checking; all secret-exclusion assertions remain in both schedules.
- Finding 3: contributors no longer depend on either `FAKE_SLEEP` in this module. Concurrent worker
  starts capture the queued record together, then the winning worker blocks on a one-byte stdin
  signal. The parent asserts the running record and absence of engine output before releasing it.
  The second schedule holds the other worker's captured queued record until the winner finishes,
  then releases that stale follower and verifies exactly one engine execution. Readiness polling
  waits for explicit markers; it never releases a worker on elapsed time. Existing version-probe
  delays and fake-clock sleeps test timeout budgets rather than schedule worker completion.

Test-first evidence: before the fixes, the running-status regression failed because the release
already existed on entry to the second wait, and forcing the environment test's follower to start
after host completion failed its old count assertion (`3` invocations instead of at least `6`). No
timeouts were increased. The file signal, stdin pipes and argv-list subprocesses work on native
Windows without POSIX signals or a shell; Windows execution is unavailable here. C1's privacy
rule and its byte-exact escaped-backslash/allowlist regressions require no C2 changes.
