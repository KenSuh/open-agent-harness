# P5 Gates, Finish Guard, Stop Hook and Hook Installation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "Done" stops being whatever an agent says. A task's gate ledger is checked by unlazy,
bound to the exact inputs it was checked against, and enforced by `oah finish`, an opt-in Claude Code
Stop hook and an opt-in git pre-push hook.

**Architecture:**
- **`oah.gates`** is the pure core: a read-only ledger parser that mirrors unlazy's strict parser,
  per-gate input manifests and digests, the binding store in runtime state, the finish guard and the
  path-free summary writer. Settings are parameters with module-level `DEFAULTS`.
- **`oah.unlazy`** finds unlazy, pins its commit and owns the whole CLI contract with
  `gate-check.mjs`, `gate-lint.mjs` and `stop-hook.mjs`. `oah` never executes a CHECK line itself.
- **Command modules** (`gates_cli`, `check_cli`, `hooks_cli`, `hook_cli`) expose
  `register(subparsers)`, `COMMANDS` and `run(args)`. `cli.py` discovery is lane P3a's.
- **`oah.hooks.install(kind, root, *, dry_run, ...)`** is the one installer for Claude Code and git
  hooks. `oah hook <name>` dispatches to `oah.hook_<name>.run(args)`.

**Tech Stack:** Python 3.11+ stdlib (`hashlib`, `json`, `difflib`, `importlib`, `unittest`), git and
node through `oah.engines.proc`.

**Spec:** `docs/PLAN.md` 5.4 (finish), 5.8 (gates), 5.12 (hooks), 8, 11, 13, and the lane intent p5
(amendment 3: A9–A17, of which A17 covers pre-push and keys).

## C2 acceptance checks

- [x] Every gate and Stop invocation executes a fresh owner-only state-folder snapshot of the
  complete pinned script closure; the copied commit record and digests are verified before execution.
  Replacing source scripts or directory aliases after verification cannot change the executed bytes.
- [x] `NODE_OPTIONS` preloads are refused before execution. All supplied `NODE_*` runtime variables
  are mandatory evidence inputs, including case-insensitive Windows names; changing them stales bindings.
- [x] Replacement regressions use real files and child processes; the requested full unittest suite
  passes (417 tests, 24 skipped), as do all five real pinned-unlazy probes. Windows-only checks await Windows CI.

## C4 acceptance checks

- [x] Check the state directory and its ancestry before creating or copying snapshots, and recheck
  permissions after digest verification. Refuse writable parents that allow snapshot replacement.
  Trusted POSIX sticky ancestors may protect an owned child; the state root itself cannot be writable
  by group or other accounts.
- [x] Require the current user's ownership from state root through snapshot, reject symlinks/reparse
  points and unproven ACLs, and verify Windows owners and DACLs along the same chain. New Windows
  directories have an explicit current-user owner and protected owner-only DACL. Refusals identify
  the first offending directory and give permission-repair or `OAH_STATE_DIR` guidance.
- [x] Regressions cover a real child-process snapshot replacement attempt, writable ancestors,
  ownership, links and macOS parent ACL grants. Portable Windows descriptor tests cover unsafe
  parent grants and owners; actual Windows ACL tests remain guarded for Windows CI.

## Global Constraints

- Everything from the P1 and P2 plans still applies: stdlib only, never `shell=True`, UTF-8 on every
  read and write, CRLF-tolerant parsers, a Korean one-line header on new `.py` files, test writes
  inside the checkout, executables resolved through `oah.engines.proc`.
- **Exit codes:** 0 ok, 1 refused (the `OAH_*` code first), 2 usage, 69 environment.
- **Settings:** the `[gates]` section, read with `load_config(root).section("gates", DEFAULTS)` in the
  command modules and the Stop hook: `commit_ledgers` (false), `stop_max_blocks` (6), `input_env` ([]),
  `check_timeout` (120). Unknown keys and wrong types exit 69 (`OAH_CONFIG_UNKNOWN_KEY`,
  `OAH_CONFIG_INVALID`).
- **unlazy pin:** upstream `https://github.com/Leonxlnx/unlazy`, commit
  `16671491f6679ad9378f52604d3bc2415b4120c7` (package version `2.1.0`, unreleased source target).
  The contract below is written against that commit.
- **unlazy CLI contract (pinned):**
  - `node <dir>/scripts/gate-check.mjs [--status | --reverify] [--approve] [--cwd DIR] [--root DIR]
    [--timeout S] -- <ledger>`. Exit 0 `ALL MET (<n> met…)`; exit 1 `UNMET: <n> (…)` and/or
    `HANDOFF REQUIRED: <n> abandoned (…)`; exit 2 usage, parse or infrastructure; exit 3 lease
    conflict (not used by `oah`). `--status` lists `  UNMET <stem>:<id> (<reason>): <title>`. A run
    without approval prints `APPROVAL REQUIRED` and `NOT RUN`, and executes nothing.
  - `node <dir>/scripts/gate-lint.mjs [--strict] [--json] -- <ledger>`. Exit 0 `LINT OK`; exit 1
    `LINT FINDINGS` (strict); exit 2 usage or parse failure.
  - `node <dir>/scripts/stop-hook.mjs` reads the Claude Code Stop payload on stdin and prints nothing,
    `{"systemMessage": …}` or `{"decision": "block", "reason": …}`; it always exits 0.
  - `oah` passes `--approve` only when the user typed `oah gates check --approve`.
- **unlazy discovery:** `OAH_UNLAZY_DIR` (authoritative), then `<repo>/.agents/skills/unlazy`,
  `<repo>/.claude/skills/unlazy`, then the same under the user's home. Resolve the discovered directory
  to an absolute path before pin verification and use it for every subprocess.
- **unlazy pin (owner decision after PR #9):** `oah.unlazy.PIN` holds the pinned commit and the sha256 of
  every script oah calls plus everything they load (LF-normalized). A discovered copy is used only when
  it is a git checkout of its own at that commit and every digest matches; anything else is refused with
  `OAH_UNLAZY_UNPINNED` and the pinned install command. `install_commands(target)` / `install_hint(target)`
  give that command for `oah init` (P7b); the unversioned `npx skills add` form is never printed. unlazy
  is looked up only when a ledger governs, so a task without gates never needs it. A new commit is
  adopted only by updating `PIN` and passing `ContractTest`, `PinTest` and `PinnedUnlazyProbeTest`
  (which checks that the pin covers the scripts' whole import closure).
- **Ledger:** `.oah/tasks/<task>/GATES.md` by default. A lease may declare ledgers explicitly
  (`oah start --gates PATH`); with none declared, the default ledger counts when it exists.
- **Lease record:** gains an optional `gates: list[str]` (repo-relative ledger paths). The schema stays
  version 1, and records without the field still load.
- **Inputs:** per gate, a manifest of `(path, mode, sha256)` over every tracked and non-ignored
  untracked file of the worktree, including deletions (`mode = deleted`). Generated gate outputs are
  excluded: `.oah/tasks/*/GATES.md`, `.oah/tasks/*/GATES.summary.md`, `.unlazy/**` and
  `.unlazy-hook-state.json`. A gate may narrow its inputs with an indented `OAH-INPUTS: a, b/c` line
  (repo-relative path prefixes; unlazy ignores the line). Governed custom ledgers are also excluded;
  their definitions and evidence are validated separately. Submodule inputs refuse verification until
  live contents can be covered. The digest also covers the Python version, platform, configured
  `input_env` names, mandatory PATH/shell/Node selection and resolved runtime file identities.
- **Bindings:** `<state_dir>/gates/<task>/bindings.json`, keyed by ledger path then gate id:
  `{kind: run|carry, definition, title, evidence, inputs, carry?: {old_inputs, new_inputs, evidence}}`
  (all sha256 hex). Written under the state lock, atomically. Run results must match the original
  definition and input declaration; explicitly discarded STALE results never receive bindings.
- **Summary:** `.oah/tasks/<task>/GATES.summary.md`, written by `oah gates check` once the task's gates
  pass, so it is committed and reviewed with the work. `oah finish` writes nothing tracked: it refuses with
  `OAH_GATES_SUMMARY_MISSING` or `OAH_GATES_SUMMARY_STALE` unless the file matches the current gate records
  (a structural-only finish has no summary). Grammar, line by line:
  `# oah gates summary v1`, `verified: unlazy|structural`, `ledger: <sha256>`, then per gate
  `G<n> <met|abandoned> binding=<run|carry|none> title=<sha> check=<sha|none> expect=<sha|none>
  evidence=<sha> inputs=<sha|none>`. The writer validates every line against this grammar and refuses
  anything else with `OAH_SUMMARY_FIELD_REJECTED`. `[gates] commit_ledgers = true` skips it.
- **Hooks:** Claude Code entries are exactly `{"type": "command", "command": "oah hook <kind>"}` in
  `.claude/settings.local.json` (default) or `.claude/settings.json` (`--shared`). Git hooks are
  `#!/bin/sh` scripts in `git rev-parse --git-path hooks` that `exec oah hook <kind> "$@"`. A changed
  file is backed up as `<file>.oah.bak` before the first write; a foreign git hook is replaced only
  with `--force` and restored on uninstall. Only exact generated hooks are managed; modified hooks
  require the same forced replacement and backup, and uninstall preserves them.

- **Wiki maintenance exemption (PLAN 5.10):** when `docs/wiki/` exists, `finish` requires an available
  `oah.wiki` verifier and calls `verify_maintenance(root, task)`. Only `docs/wiki/log.md`,
  `docs/wiki/index.md` and a newly created `docs/wiki/log_archive_NN.md` whose current bytes match the
  reported digest are exempt from the scope
  check, recorded in the finish event. A failed check refuses with `OAH_WIKI_MAINTENANCE_MISSING` unless
  `--allow-missing-wiki-maintenance` is given (recorded).

## Review Focus

1. **A gate's CHECK is unchanged but source changed.** `finish` refuses with `OAH_GATES_STALE` even
   though unlazy still reports the gate met; `gates check` runs unlazy with `--reverify`.
   → `test_unchanged_check_with_changed_source_reverifies`, `test_finish_rejects_stale_binding`.
2. **Inputs change while unlazy runs.** The run's bindings are discarded. →
   `test_inputs_changed_during_check_invalidate_run`.
3. **A failing rerun.** It blocks finish. → `test_failing_rerun_blocks_finish`.
4. **Summary privacy.** A fixture with absolute paths, user names and emails in every free-text field
   produces a summary where every line matches the grammar and none of the planted strings
   survives. → `test_summary_keeps_only_ids_enums_and_digests`.
5. **Approval boundary.** `oah` never adds `--approve` on its own and never runs a CHECK line. →
   `test_check_without_approve_flag_never_passes_approve`.
6. **Stop hook cannot wedge.** It releases after `stop_max_blocks` blocks without progress, and any
   internal error allows the stop with a message. → `test_progress_guard_releases`,
   `test_internal_error_allows_stop`.
7. **Abandonment is a handoff, never success.** `finish` passes but prints
   `OAH_GATES_HANDOFF_REQUIRED` and records `gates=handoff`. (Builder's call: a genuinely impossible
   gate must not trap the lease; the summary marks it `abandoned`.)
