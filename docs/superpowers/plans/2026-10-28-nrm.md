# nrm Evidence-Backed Effort Normalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Codex run counts as effort-verified only through a shipped rule that names one exact CLI
version and exact model names, maps only labels proven from public source at a pinned commit, and
carries that evidence. The recorded basis says the mapping is expected from source, never that the
backend served that effort.

**Architecture:**
- **One matcher:** `normalize` (and `verify_inference`, which calls it) stays the only matching code.
  A rule's typed `match` field picks the policy: absent means the legacy prefix/glob behaviour for
  rules a caller passes in; `"exact"` means whole-string equality for versions and models; any other
  value never matches.
- **Strict loader:** `load_rules()` reads the shipped file and hands it to `parse_rules(text)`,
  which accepts only exact, evidence-backed rules over the proven labels and refuses anything else
  with `OAH_NORMALIZATION_RULE_INVALID`.
- **Honest basis:** an evidence-backed match records
  `<rule id>: expected mapping from CLI source at <commit>; not observed served effort`.

**Tech Stack:** Python 3.11+ stdlib (`json`, `re`, `fnmatch`, `importlib.resources`, `unittest`).

**Spec:** `docs/PLAN.md` (5.5 effort resolution, header check and normalization; 8 tests); intent
`nrm` revision 1.

## Global Constraints

- Everything from the earlier plans' Global Constraints still applies: stdlib only, UTF-8 on every
  read, no network, no live Codex or provider call, no reading `~/.codex` or any transcript.
- **Evidence is public and cited, never copied.** The shipped rule cites `openai/codex` at tag
  `rust-v0.164.0`, commit `6aaac694803004a63c6f393d153c96d22521a6b9`, by file:line only.
- **Legacy semantics are kept unchanged.** A caller-supplied rule without `match` still matches
  versions by prefix (`"*"` matches any) and models by `fnmatch.fnmatchcase`, and its basis stays
  its id. Every existing effort test except the one that asserted an empty shipped file keeps
  passing unchanged.
- **Nothing widens.** Runs on other CLI versions, other models, or labels outside the proven set
  stay `unverified` exactly as today.

## Review Focus

- `match: "exact"` uses `==` for both version and model; `0.164.1`, `0.164.01`, `0.164.0-dev`,
  `0.164`, `""` and `None` never match `0.164.0`.
- `parse_rules` refuses: a missing or wrong `version`, an unknown key, a missing or non-exact
  `match`, a version that is not a plain `MAJOR.MINOR.PATCH` (prefix, wildcard, pre-release, leading
  zero), a model with glob characters, a label outside `low medium high xhigh max`, a non-identity
  mapping, a missing or malformed evidence object (kind, repository, 40-character commit, file:line
  references), missing assumptions, a duplicate id.
- The header check still compares configuration labels; a downgraded or mismatched header still
  fails; `ultra`, `persistent`, `none`, `minimal` and custom labels stay unverified.
