# RREC C1: occurrence-based review recurrence

## Problem

A finished correction marks a defect class as attempted. Using that class (or an
equivalent mechanism/rule definition) for a distinct finding currently stops a
progressing review series, even when no earlier occurrence is referenced.

## Decision

Only a valid `prior_refs` entry naming a finding targeted by a finished correction
is recurrence evidence. Match the earlier round, receipt digest, finding ID and
that finding's class ID against the series history, then match the correction's
source digest and finding IDs. The current finding may use another class, wording
or location. A shared class, definition or location alone never proves recurrence.

For blocking findings without that tie, keep `changes-requested` and record
`<finding>: new instance of attempted class <id>` in a new receipt `new_instances`
list and the headline when the class ID or normalized definition was attempted.
Decision/scope stops still take precedence; nonblocking findings remain follow-ups.
Earlier-series class matches without a valid series occurrence tie also continue.
Keep the existing history/reference validation refusal: invalid references never
count as recurrence evidence in `decide`, and `check` still refuses to count a
round with broken references. The prior reference's class must match its historical
finding, but need not match the current finding's class.

The prompt must request occurrence references for the same problem regardless of
wording or class ID, while leaving references empty for distinct instances.
No round cap or change to other review gates is needed.

User-visible change (finding 1): new defects in attempted classes continue with an
explicit new-instance label; a referenced corrected defect still asks for a decision.
