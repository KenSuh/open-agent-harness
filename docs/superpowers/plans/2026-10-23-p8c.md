# P8c Optional Companion Apps (Orca and Aside) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Guided setup offers two optional apps, Orca and Aside. It installs each only with consent from
its official source, walks the user through the CLIs and sign-in without touching an account, registers
Aside's MCP server for Claude Code and Codex with consent, and offers an optional rules section.

**Architecture:**
- `oah.setup.companions` holds the two catalog entries (`companion_tools()`), the post-install steps
  (`plan_steps`, `run_steps`, `companion_setup`) and `rules_section`. Collaborators (`which`, `ask`,
  `out`, `runner`, `probe`) are parameters, so tests run against fakes.
- `oah.setup.tools` gets the smallest hook: an `optional` field on `Tool` (its `requirement` becomes
  `"optional"`) and `catalog()` appending `companion_tools()`. P8's doctor and guided installer then list,
  check and offer both apps unchanged.
- `python -m oah.setup.companions` runs the post-install steps for one project until lane P7b wires
  `companion_setup` into `oah init`.
- Templates under `src/oah/templates/companions/`: the rules section in English and Korean, and the
  vendor's Windows CLI installer procedure.

**Tech Stack:** Python 3.11+ stdlib.

**Spec:** `docs/PLAN.md` 5.11, 6.5, A13, A17, amendment 5 (A20), and the lane intent `p8c` r1.

## Global Constraints

- Everything from the P1, P2 and P8 plans still applies: stdlib only, never `shell=True`, UTF-8 on every
  read and write, a Korean one-line header on new `.py` files, executables resolved through
  `oah.engines.proc` and never a `.cmd`/`.bat` launched directly.
- **Official sources only.** Orca: `brew install --cask stablyai/orca/orca` (never the unrelated plain
  `orca` cask), `winget install --id StablyAI.Orca -e`, https://www.onorca.dev/download and
  https://www.onorca.dev/docs/install. Aside: `brew install --cask aside`,
  https://aside.com/download?os=mac, https://aside.com/download?os=win; Linux is not supported.
- **Commands checked against the tools' own help.**
  - `orca skills install` without `--skill`/`--all` only lists skill names, so the step runs
    `orca skills install --all` (global by default, needs `npx`).
  - `orca project setup-existing-folder --project <id> --host <host> --path <path> [--kind git|folder]`.
    Its help gives the id form `github:<owner>/<repo>`, so the step uses `--project github:<owner>/<repo>
    --host local --path <root> --kind git` only when `origin` is a GitHub remote. Any other project gets
    an instruction to add the folder in Orca instead of a guessed id.
  - The Aside CLI installer is the vendor's: macOS `curl -fsSL https://releases.aside.com/install.sh | bash`
    run as `/bin/sh -c <text>`; Windows the signed-installer procedure from
    https://docs.aside.com/help/developers, shipped unchanged as a template and run with
    `powershell -NoProfile -ExecutionPolicy Bypass -File <template>`. Its full text is shown first.
- **Consent.** The whole plan is printed first. Each step that runs a command asks `[y/N]`; `yes=True`
  covers only the steps in the printed plan. Optional CLI installation additionally requires the app
  in `with_optional` (the entry point passes explicit `--app` selections), or an interactive yes.
  Steps that write outside the project carry `[global]`.
  A dry run prints the plan and runs nothing, not even a check.
- **No account data (A17).** Sign-in is the user's own action in Aside and `aside login` in their own
  terminal. `aside account status` must report `signed in` in its status column, not just exit zero;
  signed-out, paused and unknown states stay pending. Identity fields are never extracted. MCP checks
  validate `aside mcp` over stdio: `claude mcp get aside` must show user scope and connected status;
  `codex mcp get aside --json` must show enabled. Conflicting, disabled or unverified entries stay
  pending and unchanged; users repair them in their coding agent before retrying. Output is discarded
  without printing or saving it. Claude registration uses
  `claude mcp add --scope user --transport stdio aside -- aside mcp`.
- **Exit codes.** `python -m oah.setup.companions`: 0 when every chosen step is done or already present
  (a dry run is 0), 1 when a step was skipped, failed or is pending, 2 usage. Last line
  `COMPANIONS_OK`, `COMPANIONS_INCOMPLETE pending=<keys>` or `COMPANIONS_DRY_RUN steps=<n>`.

2. **Account data.** Any path where `aside` or MCP output reaches `out`, stderr, a log or a file. →
   `test_probe_output_is_never_shown`, `test_cli_never_prints_account_data`.
