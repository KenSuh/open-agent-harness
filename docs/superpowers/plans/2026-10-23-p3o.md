# P3o Optional Orca Launcher for `oah call` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** when Orca is installed and selected, `oah call` runs the worker in an Orca worktree terminal,
keeping P3b's routing, brief, run record and honesty rules. Without Orca or without the selection,
nothing changes.

**Architecture:**
- **One prepared run, two launchers.** `oah.call.prepare` stays the only place that decides engine,
  tier, model, effort, brief and argv. A launcher only decides *where* the prepared run executes.
  `process` (the default) is P3b's foreground run or detached background runner, untouched.
- **Orca runs oah's own runner, not the engine.** The Orca launcher writes `launch.json` exactly as
  P3b's background path does, then asks Orca for a terminal whose command is
  `oah worker-run <run-id>; exit`. Inside the terminal, `oah worker-run` calls P3b's `execute`, so the
  brief goes from `prompt.md` to the engine's stdin byte for byte, the worker gets `OAH_WORKER`,
  `OAH_RUN_ID` and `OAH_TASK`, a review stays read-only, and the header and effort checks run as they
  do today. Before execution, the runner binds `launch.json` to its queued run using a recorded digest,
  checks identity, paths, stage routing and review permissions, reconstructs the worker variables and
  atomically claims the run under the state lock. A second claimant refuses. Orca never sees the brief text.
- **`oah wait` follows the terminal.** It loops on `orca terminal wait --for exit` in slices inside the
  9-minute bound, copies new terminal output into `terminal.log` with bounded `orca terminal read`
  pages, and returns the record. `result.json` written by the runner is the source of truth; a
  terminal that exits without a final record makes the run `lost`. Waits, reads and previews share one
  deadline; every subprocess timeout is capped by the remaining budget and paging stops at expiry.

**Tech Stack:** Python 3.11+ stdlib. `orca` is reached only through `oah.engines.proc.run_command`
with argv lists and `--json`. Tests use `tests/fakes/fake_orca.py`, a fake CLI plus a fake host
process, and the existing fake engines.

**Spec:** `docs/PLAN.md` section 4 row 8, 5.3, 5.5 (launching and run records), 8, A1, A6, A17, and
amendment 5's A20 as written into the lane intent (p3o r1).

## Global Constraints

- P1–P3b constraints still apply: stdlib only, never `shell=True`, UTF-8 on every read and write,
  parsers accept CRLF, a Korean one-line header on new `.py` files, test writes inside temp folders.
- **Exit codes:** 0 ok; 1 refused; 2 usage; 69 environment (`OAH_LAUNCHER_UNAVAILABLE`,
  `OAH_LAUNCHER_FAILED`); 75 `oah wait` returned while the run still goes.
- **Config** (`oah.config`, core logic stays config-free):
  `[call] launcher = "process" | "orca"` (default `"process"`) and
  `[call] orca_command = ["orca"]`. `orca_command` follows `[engines.*] command`: a bare name is found
  on PATH through `oah.engines.proc` (batch shims are refused as everywhere else), a path is used
  literally, so Windows users with a `.cmd` wrapper can set `[interpreter.exe, script]` (5.3).
  `--launcher` on `oah call` overrides the config for one call. An unknown launcher name in the config
  is `OAH_CONFIG_INVALID` (69).
- **No silent fallback (AC1).** With Orca selected, a missing `orca`, a failing `orca --version`,
  a missing `oah` on PATH (the terminal needs it to start the runner) or an `OAH_STATE_DIR` override
  (Orca's terminal cannot inherit it) refuses with `OAH_LAUNCHER_UNAVAILABLE` before any run folder,
  worktree or terminal exists. The message names the install page
  (`https://www.onorca.dev/docs/install`), `[call] orca_command`, and how to run without Orca.
- **Documented Orca commands only (AC2),** checked on 2026-10-23 against Orca 1.4.237
  (`orca skills get orca-cli`, `orca help <command>`, `orca agent-context --json`), always with `--json`:
  - `orca --version`;
  - `orca worktree show --worktree path:<dir>|id:<id> --json` → `result.worktree.{id, repoId, path,
    hostId}`;
  - `orca worktree create --repo id:<repoId> --name <name> --no-parent --json` → `result.worktree.id`
    (then confirmed with `worktree show`);
  - `orca terminal create --worktree id:<id> --title <title> --command <text> [--shell powershell.exe]
    --json` → `result.terminal.{handle, processId, hostPlatform}`;
  - `orca terminal wait --terminal <h> --for exit --timeout-ms <ms> --json` → `result.wait.status`
    `exited` with `satisfied: true` and `condition: "exit"`, or `ok: false` with `error.code = "timeout"`;
  - `orca terminal read --terminal <h> --cursor <c> --limit <n> --json` →
    `result.terminal.{tail[], nextCursor, latestCursor, limited}`;
  - `orca terminal show --terminal <h> --json` → `result.terminal.preview` (kept after exit; a read
    after exit returns no lines).
  Invalid envelopes, inconsistent process exit codes and malformed command fields are
  `OAH_LAUNCHER_FAILED`, including during foreground waits.
- **Where the run executes (AC2).** With `--worktree`, P3b resolves exactly one worktree and Orca must
  know it (`worktree show --worktree path:<dir>`). Without it, the launcher creates an independent
  Orca worktree named `oah-<task>-<8 hex>` from the repository's default base, and the call then
  behaves exactly like `--worktree <that path>`: config, packet and Codex `-C` all come from the new
  checkout, so uncommitted packet or config edits in the current checkout are not in it. If `prepare`
  refuses after the worktree was created, the worktree is kept and the message says how to reuse it.
  Only the local execution host is supported; a worktree on another host is `OAH_LAUNCHER_FAILED`.
- **Generated command (AC5).** The terminal command is `oah worker-run <run-id>; exit`. The only value
  in it is the run id, checked with P3b's `briefs.shell_word` (`[A-Za-z0-9._/-]+`), so no quoting is
  needed in sh, zsh, bash, fish or PowerShell. On Windows the terminal is created with
  `--shell powershell.exe` (Windows PowerShell 5.1 understands `;` and `exit`). No path is ever placed
  in the command; the runner finds the state folder from the terminal's working directory (the
  worktree) through git.
- **Honesty (AC3, A1, A6).** `result.json` gains one field, `launcher`, `null` for process runs. For
  Orca runs it holds `{name: "orca", orca_version, worktree, worktree_id, worktree_created, terminal,
  terminal_process_id, host_platform, command, worker_env, reported_model, reported_effort,
  terminal_cursor, launch_digest}`. `requested_model`, `requested_effort`, `launch_effort`, `header_*` and
  `resolved_inference_effort` keep P3b's meaning and are filled by the runner. Orca's terminal API
  reports neither model nor effort, so `reported_model` and `reported_effort` are `unverified`.
  `worker_env` is `env`, because `oah worker-run` sets the three worker variables in the engine's
  environment itself; the `brief-only` case of the intent does not arise with this design, and the
  brief's worker line carries them in every case.
- **No credentials (A17).** Only allowlisted OS paths and locale variables reach Orca, including its
  version probe. Engine credentials remain in the worker environment; nothing reads or stores a key.
  Orca's account state is never touched. Tests configure fake Orca through its explicit state path
  and control file rather than forwarding caller environment variables.
  Nothing global changes: no global file, no Orca setting, no repo registration.

## Review Focus

1. **A beginner selects Orca without having it.** The call refuses with
   `OAH_LAUNCHER_UNAVAILABLE`, exit 69, the install pointer, and no run folder, worktree or engine
   process. → Task 2 `test_missing_orca_refuses_and_launches_nothing`,
   `test_disabled_orca_cli_refuses_and_launches_nothing`.
2. **The brief reaches the worker byte-intact through Orca,** including CRLF and non-ASCII intent
   bytes, and Orca's argv carries none of it. → Task 3
   `test_new_worktree_run_delivers_the_exact_brief_and_records_orca_ids`,
   `test_existing_worktree_keeps_crlf_intent_bytes`.
3. **`oah wait` on an Orca run** returns 75 within the requested bound while the worker runs, the final
   record after exit, never asks Orca for more than the 9-minute bound in total, and reports `lost`
   when the terminal exits without a result. → Task 4.
4. **The default path is untouched.** All of `tests/test_call.py` passes unchanged, and a process run
   records `launcher: null`. → Task 1 `test_process_run_records_no_launcher`, plus the full suite.
5. **The generated terminal command** holds only safe characters on both OSes and uses PowerShell on
   Windows. → Task 3 `test_runner_command_is_safe_and_portable`,
   `test_windows_terminal_runs_powershell` (Windows only).

## Rejected alternative

`orca worktree create --agent <engine> --prompt <brief> --model --effort` (Orca's agent launch) was
not used: it puts the brief on argv (the Windows 32K limit), starts the engine interactively with
Orca's own flags (a review would not be read-only), cannot pass the worker variables, and leaves no
stdout or header for P3b's effort checks. Running oah's runner in an Orca terminal keeps every P3b
guarantee and still gives a visible, supervised terminal per worker.

  with the validated snapshot, printing one line before and the summary after.

### Task 4: Following the terminal in `oah wait`

**Files:**
- Modify: `src/oah/launchers/orca.py`, `src/oah/call_cli.py`, `tests/test_launcher_orca.py`

**Interfaces:**
- `orca.wait(orca, state_dir, run_id, *, timeout, slice_s=WAIT_SLICE_S) -> dict`: at most
  `call.WAIT_LIMIT_S` in total, in `terminal wait` slices of at most 30 s; after each slice it pages
  `terminal read` (at most 5 pages of 200 lines) into `terminal.log` and stores the cursor. An exited
  terminal without a final record, or a vanished terminal whose runner pid is gone, records `lost`
  (`OAH_RUN_LOST`) with the terminal preview appended to `terminal.log`.
- `oah wait <run-id>` dispatches on the record's `launcher`; a foreground `oah call --launcher orca`
  waits the same way until the run ends.
