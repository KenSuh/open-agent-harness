# P3b Routing, Engines, Call and Run Records Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** route each stage to its engine, pick the model and effort by difficulty, launch Claude Code
or Codex safely on macOS and Windows, and record what really ran. The commands are `oah recommend`,
`oah call`, `oah wait` and `oah models`.

**Architecture:**
- **Pure core, thin commands.** `routing`, `engines/effort`, `engines/codex`, `engines/claude`, `models`,
  `runs` and `briefs` take settings as parameters and keep module-level `DEFAULTS`. Only the
  `*_cli.py` modules read `.oah/config.toml` through `oah.config`.
- **One launch path.** `oah.call` builds the brief and argv, writes the run folder, and launches through
  `oah.engines.proc.run_command`, which kills the whole process tree on timeout. `--background`
  starts a detached Python runner for the same run folder and returns the run id at once.
- **Every value is recorded separately:** requested, launch, header-reported and resolved inference
  effort; requested and effective model and their sources; the difficulty axes, tier and tier source.
  Unavailable values are `unverified`.

**Tech Stack:** Python 3.11+ stdlib (`tomllib`, `json`, `subprocess` through `oah.engines.proc`,
`importlib.resources`, `unittest`). Fake engines are Python scripts in `tests/fakes/`.

**Spec:** `docs/PLAN.md` 5.0, 5.3, 5.5, 5.6 (briefs and footer), 5.9 (trailers), 8, 15 (P3: A1, A6, A7,
C1–C4); amendment 3 items A10 and A14 as written into the lane intent.

## Global Constraints

- P1/P2 constraints still apply: stdlib only, never `shell=True`, UTF-8 on every read and write,
  parsers accept CRLF, a Korean one-line header on new `.py` files, test writes inside the checkout.
- **Exit codes:** 0 ok; 1 refused (the `OAH_*` code first on stderr); 2 usage; 69 environment;
  75 `oah wait` returned while the run is still going (call it again).
- **Config defaults** (`[stages]`, `[engines.claude]`, `[engines.codex]`, `[models]`), following the
  plan PR's 5.5 excerpt for A14:
  - stages `initial = "claude"`, `review = "codex"`, `correction = "codex"`;
  - Claude: `command = ["claude"]`, `quality_order = ["opus", "sonnet", "haiku"]`, tiers with
    `model = ""` and efforts low/medium/high/max, timeouts 15/30/60/90 minutes,
    `permission_mode = "acceptEdits"` and `tools` for work stages; a review always runs in `plan` mode
    with `Read`, `Grep` and `Glob` only, whatever the config says;
  - Codex: `command = ["codex"]`, `quality_order = []`, tiers with `model = ""`, efforts
    low/medium/high/`highest`;
  - `[models] ttl_hours = 24`.
- **Model precedence (A14):** an explicit tier `model` is a pin and always wins. Then the automatic
  catalog mapping:
  - a quality list (Claude's default, or a user list for Codex), filtered to models the CLI reports:
    low uses the last available entry, medium the second (or the first if only one), high and max
    the first;
  - Codex without a user list: a model the CLI's list marks as default (`is_default` or `default`
    true); otherwise the effective configured model.
  Then 5.5's resolver: Codex's effective configuration for the launch directory
  (`$CODEX_HOME/config.toml`, then `<dir>/.codex/config.toml`, then the selected `profile`'s
  `[profiles.<name>]`, later layers winning). Nothing resolvable refuses with `OAH_MODEL_UNRESOLVED`.
- **Catalog (`<state>/models/`):** `catalog.json` per engine `{cli_version, checked_at, models[{name,
  efforts[], default}], source}`; `resolved.json` holds the last resolved model and effort per engine
  and tier; `changes.jsonl` gets one `{ts, engine, tier, field, old, new, why}` line per change.
  Every launch probes `<cli> --version`; a changed version, an expired TTL or `--refresh` rebuilds
  the catalog. A rebuild that reads no models keeps the last good catalog and warns
  (`OAH_MODELS_REFRESH_FAILED`), never downgrading.
- **Effort (A1):** ordinary levels are ordered `none < minimal < low < medium < high < xhigh < max`.
  `ultra` is behaviour-changing and never chosen by `highest`, never compared as an ordinal.
  Normalization rules ship in `templates/engines/normalization.json`, keyed by engine, CLI version
  prefix and model pattern; anything else is `unverified`. The shipped rule list is empty until
  model/version-specific normalization evidence is recorded. A failed refresh retains the catalog
  mapping, but launch records and normalization use the current version probe, or unknown.
- **Briefs (C2):** worker line, preamble, intent section verbatim, round instructions, verify footer,
  intent footer. Stored briefs reuse content inside a fresh envelope for the current dispatch, with
  intent bytes preserved. Each footer is detected only by its marker as a whole line at line start
  (C4). Generated commands use POSIX shell quoting on macOS and PowerShell quoting on Windows.
- **Run folder:** `<state>/runs/<task>/<run-id>/` with `prompt.md`, `stdout.log`, `stderr.log`,
  `result.json` (and `launch.json` for background runs). It is created under a temporary name and
  renamed into place.
  Result merges use the state lock with forward-only status transitions; background runs are queued
  before launch. Windows refuses background dispatch if job breakaway is denied. Creation, lookup and
  intent binding enforce containment beneath the resolved state root, including directory aliases.
- **Intent lineage (coordinator note 3, A7/C1–C4):** briefs carry the intent section exactly as
  `oah.intent.read_source` returned it (`briefs.raw_section`), plus the one shared footer
  (`briefs.intent_footer()`, which lane P7b installs into role definitions). The first dispatch with a
  packet writes `runs/<task>/intent-binding.json`; later rounds reuse that source, and a different
  source, Intent-ID, in-place edit, older revision or stored brief with another section refuses with
  `OAH_INTENT_SOURCE_MISMATCH`. `--worktree <path|branch|name>` must name exactly one worktree before
  any intent is read; otherwise `OAH_WORKTREE_UNRESOLVED` (ambiguous or unknown) with runnable retry
  commands.
- **No keys.** Nothing in this lane reads a key. The worker environment is the caller's plus
  `OAH_WORKER=1`, `OAH_RUN_ID` and `OAH_TASK`; no environment value is written to a run record.

## Review Focus

1. **An effort is lowered or guessed silently.** → `test_highest_skips_ultra`,
   `test_highest_without_metadata_refuses`, `test_lower_header_is_downgraded`,
   `test_ultra_label_is_not_ordinal`, `test_unknown_normalization_is_unverified`.
2. **A review is launched writable, or on the wrong engine.** → `test_review_is_read_only_codex`,
   `test_review_is_read_only_claude`, `test_stage_mismatch_refuses`, `test_override_stage_is_recorded`.
3. **A timeout leaves a grandchild running.** → `test_timeout_kills_process_tree`.
4. **A brief loses, duplicates or fakes its footer.** → `test_mention_of_marker_still_gets_footer`,
   `test_stored_brief_with_two_footers_refuses`, `test_missing_footer_refuses_dispatch`.
5. **A model change goes unlogged, or a lost refresh downgrades.** → `test_new_default_model_adopted_and_logged`,
   `test_lost_metadata_keeps_last_good_mapping`, `test_pin_wins_over_catalog`.
