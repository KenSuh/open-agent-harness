# P7i Impact Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oah impact` answers "if I change X, what must I re-check?" from a map persisted in the state
folder. The map records a freshness identity and is refreshed incrementally; it is never used silently
while stale. A default SQL plugin turns migrations into DB entities linked to code.

**Architecture:**
- **Core package `oah.impact`** is config-free. Every setting is a parameter, with module-level
  `DEFAULTS`. `impact_cli.py` merges settings over the defaults (later through `oah.config`).
- **Map:** one JSON file per worktree, `<state>/impact/maps/<sha256(worktree root)[:16]>.json`,
  written atomically under its own lock (`<state>/impact/.lock`, 120 s). The shared lease lock is
  never held during a build.
- **Inputs:** the map reads the working tree: tracked files and untracked, non-ignored files, with dirty
  edits as they are on disk. History comes from HEAD. `--ref REV` builds an in-memory map of a commit.
- **Identity (plan review, PR #9):** an input manifest of
  - `worktree` (which checkout) and `head`;
  - `index`, the sha256 of `git ls-files -s`;
  - `dirty` and `untracked`, the sha256 of each such file's bytes (`deleted` for a removed tracked file);
  - `ledgers`, every `.oah/tasks/*/GATES.md` including ignored ones;
  - `config`, the bytes of `.oah/config.toml`;
  - `tool`, the sha256 of the oah version, the map schema, the impact package's source bytes and the
    settings in `MAP_KEYS`.

  `result` is the sha256 of the canonical JSON of the map's data. A map is fresh only when the manifest
  and the result both match. Status reads take no index lock (`--no-optional-locks`). The state folder
  is never an input.
- **Moving inputs:** the manifest is taken before and after every build. If it moved, the build is
  retried, up to 3 attempts in all; when it keeps moving, the map is not stored and the command refuses
  with `OAH_IMPACT_STALE`.
- **Incremental refresh** compares per-path input keys (index blob for clean files, byte digest otherwise)
  and produces byte-identical data to a full build of the same inputs. Tests compare the result digests.

**Tech Stack:** Python 3.11+ stdlib, git through `oah.engines.proc.run_command`.

**Spec:** `docs/PLAN.md` 4 (rows 16–18), 5.10, 15 (P7: A2, A3, A4), lane intent p7i (A11).

## Global Constraints

- Everything from the P1 and P2 plans' Global Constraints still applies: stdlib only, never
  `shell=True`, UTF-8 on every read and write, CRLF accepted, a Korean one-line header on new `.py`
  files, test writes inside the checkout.
- **Exit codes for `oah impact`:** 0 ok, 2 usage (argument parsing), 1 query errors, 69 environment.
  Messages start with an `OAH_*` code and say what to do next.
- **Never silently stale (A11).** `ensure_fresh(root, refresh=True)` builds or refreshes a stale map;
  with `refresh=False` it raises `OAH_IMPACT_STALE` (exit 69). A missing, unreadable, older-tool or
  digest-mismatched map is stale.
- **Ranking:** binding `pin > exec > link > mention`, then layer order
  `gates, lexical, db, wiki, graph, cochange`, then score, then path. Pin and exec rows are never
  capped. Weaker rows are capped at `limit` (50). Every output ends with
  `total=<n> shown=<n> overflow=<n>`.
- **Every output reports `rerank=...` (A2).** One call site, `query.apply_rerank`. A provider runs only
  when `[impact] rerank = true` enables it explicitly and its key is present. Reasons, in order:
  `disabled-by-brief` (`--no-rerank`), `not-enabled`, `not-configured` (no provider until lane P3b
  lands `oah.rerank.rerank`), then P3b's `no-key`.
- **Every output reports a `db-impact:` line (A3).** It names the graph identity, or says
  `db-impact: unavailable (no SQL migrations found)`.
- **Empty Scope (A4).** Selecting targets from a task's Scope warns `OAH_SCOPE_EMPTY` and falls back
  to the whole repository; a Scope or kind filter that matches no file warns `OAH_SCOPE_NO_MATCH`.
- No key, credential or personal path enters any file (A17).

## Review Focus

- Incremental refresh equals a full build (same result digest) across add, modify, delete and rename.
- Stale maps are refreshed or refused; never answered from silently.
- Binding classification of command lines (pin vs exec) and of gate CHECK/EXPECT text.
- SQL extraction tolerates Postgres, MySQL and SQLite syntax, comments, string literals, dollar quotes,
  `DELIMITER` blocks and `BEGIN … END` bodies, with correct line numbers.
- Windows: paths are POSIX inside the map, git output is parsed with `-z`, no batch files run.

## Tasks

### Task 1: Kinds and lexical matching — `oah.impact.kinds`, `oah.impact.lexical`

- `classify(path, kinds=DEFAULT_KINDS) -> str` — first matching kind of `workflow, migration, test,
  manifest, config, doc`, else `code`. `glob_match(pattern, path)` supports `**`, `*`, `?`.
- `needles_for(path, min_needle=3) -> dict[str, str]` — needle → `path|basename|stem`.
- `find_needles(line, needles) -> set[str]` — a needle matches a whole token, a `/`-suffix of a token,
  or a `/ . -` separated part of a token. `impact` does not match `impact_cli`.
- `find_identifiers(line, names) -> set[str]` — case-insensitive identifier parts (DB names).
- `classify_command(text, needle) -> "pin" | "exec" | None` — within one `&& || ; |` segment, a hash
  or grep verb before the needle pins it; a runner before it, or the needle as the command, executes it.
- `grep(root, rev, needles, *, paths=None, ignore_case=False, timeout) -> list[(path, line, text)]` —
  `git grep -n -I -F -z -f - <rev>`, patterns on stdin.
- Tests (`tests/test_impact.py`): `test_classify_kinds`, `test_glob_double_star`,
  `test_needles_skip_short_parts`, `test_find_needles_boundaries`, `test_find_identifiers_case`,
  `test_classify_command_pin_exec`, `test_grep_reads_ref_not_worktree`.

### Task 2: SQL plugin — `oah.impact.sqlplugin`

## Config (P3a, wired after the rebase)

- `impact_cli.py` reads `load_config(root).section("impact", DEFAULTS)`; config errors exit 69.
- `ensure_fresh(root)` without settings reads the same section, so every caller agrees on the tool digest
  and the map is not rebuilt back and forth.
- `defaults.effective` also checks shapes the loader cannot see (positive numbers, the `kinds` pairs) and
  refuses with `OAH_CONFIG_INVALID`.
- `[impact] sql_dialect = "standard"` is the default. Paths never select SQL semantics. Standard SQL
  keeps backslashes ordinary except in adjacent `E'...'` strings, retains hash operators and treats
  `/*! ... */` as ordinary comments. To scan MySQL migrations, set
  `sql_dialect = "mysql"` in `.oah/config.toml`; this enables backslash escapes, `#` comments and explicit
  executable-comment coverage reports. File content never selects a dialect: `DELIMITER` and
  `ENGINE=...` text retain standard semantics under the default. Standard unparsed-region reports
  suggest the explicit MySQL setting when applicable. Explicit `"postgres"` and `"sqlite"` use standard
  string/comment rules. The setting binds the map's tool digest and applies to worktree builds,
  refreshes and `--ref` snapshots. Remove it to return to the default.

- [x] Hash handling retains numeric XOR and PostgreSQL JSON hash operators and accepts MySQL hash
  comments. C5 replaces the original path-based dialect selection with standard defaults and explicit

- [x] Compound bodies retain nested DDL, indexes and the following top-level statement. The outer
  routine is scanned once; nested DDL is processed in disjoint token ranges, without recursive suffix
  rescans. Deeper quoted definitions remain reported as partial coverage.
- [x] Ledger terminal filtering uses pathlib-compatible character classes and platform casing.
  Ignored character-class ledgers invalidate freshness and dangling symlinks warn; Windows has a
  guarded symlink regression alongside the portable tests.
- [x] No SQL statement is certified as fully parsed by this dependency scanner. Every statement has
  an `unparsed` region (file, line, reason), even if dependencies were extracted; DELIMITER directives
