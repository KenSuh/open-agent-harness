# P6b Corrections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oah fix --task T` runs one Codex correction of the latest review's P0/P1 findings in the leased
worktree, records the attempt's start and its terminal outcome, shows the diff and prints the exact commit
command with `Agent-Engine: codex`. `oah fix --bind` binds the committed result to the attempt, so the next
`oah review` round counts it. Manual corrections get the same records through `oah fix --manual`.

**Architecture:**
- **One command module, one core module.** `oah.fix_cli` parses `oah fix` and maps codes to exit codes.
  `oah.review.fix` holds the four operations: `correct` (the Codex run), `bind`, `record_manual` and `abort`.
  Records are written only through `oah.review.receipts.publish` and read through `receipts.load` and
  `receipts.attempts`, in P6a's format.
- **The dispatcher owns the records; the worker owns nothing.** `oah fix` is the dispatcher: it holds the
  task's review lock (`receipts.task_lock_path`, shared with `oah review`) for the whole operation. The
  corrector is an `oah.call` worker (stage `correction`, Codex `workspace-write`, `OAH_WORKER=1`) in the
  lease's worktree. It cannot commit (`.git` is read-only in its sandbox), never touches a lease and never
  writes state.
- **Every attempt ends in exactly one outcome.** The start record is published before launch. Whatever
  happens next (finish, non-zero exit, launch failure, effort mismatch or downgrade, timeout, Ctrl-C,
  SIGTERM), one outcome record follows: `applied`, `no-change`, `failed` or `aborted`. Signals are held
  while a record is written, so a record is never half-published by an interruption. Only a hard kill can
  leave an attempt unfinished; `oah fix --abort` then records it as `aborted`, by hand.
- **Attribution is checked where it is cheapest.** `--bind` and `--manual` read the new commits' engines with
  `oah.review.authors` (the rule `oah review` uses), so binding and the next review never disagree about who
  wrote a commit.

**Tech Stack:** Python 3.11+ stdlib (`subprocess` through `oah.engines.proc` and `oah.call`, `signal`,
`hashlib`, `json`, `tempfile`, `unittest`), git, fake engine processes.

**Spec:** `docs/PLAN.md` 5.9 (the `oah fix` paragraph, correction-attempt records, Who wrote what,
`independent`), 5.6 (intent checks), 5.5 (effort verification, dispatched workers), 5.4 (scope after `fix`),
3, 5.3, 8, A1, A6, A7, A17, A22 and the P6 items of section 15 that name `oah fix` or correction attempts.
The lane brief's intent (p6b r1) is authoritative.

## Global Constraints

- Python 3.11+, stdlib only; never `shell=True`; prompts on stdin; UTF-8 on every read and write; parsers
  accept CRLF; executables resolve through `oah.engines.proc`; a one-line Korean header on new `.py` files.
- **Config-free core.** `oah fix` uses the worktree's `[stages]`, `[engines]` and `[models]` through
  `call_cli.load_settings`, as `oah call` does. It adds no config keys. `[stages] correction` must be `codex`;
  a Claude correction is recorded with `--manual --engine claude`.
- **Records (`<state>/reviews/<task>/`, P6a format, `schema: 1`):**
  - `A<k>-start.json`: `source_receipt`, `source_receipt_digest`, `finding_ids`, `class_ids` (exactly the
    classes of those findings), `before_head`, `engine`, `manual`, `started_at`, and `run_id` for a Codex run.
  - `A<k>-outcome.json`: `outcome`, `after_head: null`, non-empty `evidence`, `finished_at` (and `run_id`). The
    index line carries `outcome`.
  - `A<k>-head.json`: `after_head` (the bound HEAD), `evidence`, `bound_at`.
  - `k` is one more than the highest attempt number of the task. Nothing is ever rewritten.
- **Selection.** The source is the task's latest receipt (across bases), which must be `changes-requested`.
  Its findings are its P0/P1 findings that no `applied` attempt on that receipt covers yet; `--finding ID`
  names them explicitly (P0/P1 ids of that receipt only).
- **The corrector's environment** is `runner.reviewer_env(env)` (the reviewer's allowlist: no
  `CODEX_API_KEY`, `OPENAI_API_KEY` or other key in any letter case; proxy userinfo refuses) plus the worker
  variables. Dispatcher-owned retained or printed metadata passes `runner.credential_redactor(env)`;
  corrector streams follow C6's no-text-retention policy. Codex signs in through its own login.
- **The brief** is `oah.call`'s fixed layout. Its intent section is read from the packet as committed at HEAD
  (the bytes the review snapshot holds), so it equals the review brief's section byte for byte even with
  `core.autocrlf`. Round instructions come from `templates/review/correction.md`.
- **Codes** (first token of the message). Results: `OAH_FIX_APPLIED` (0), `OAH_FIX_NO_CHANGE` (1),
  `OAH_FIX_FAILED` (1), `OAH_FIX_INTERRUPTED` (130), `OAH_FIX_BOUND` (0), `OAH_FIX_RECORDED` (0),
  `OAH_FIX_ABORTED` (0). Refusals (1): `OAH_FIX_WORKER_REFUSED`, `OAH_INTENT_NOT_CURRENT`, `OAH_INTENT_SOURCE_MISMATCH`,
  `OAH_WORKTREE_UNRESOLVED`, `OAH_FIX_ENGINE_UNSUPPORTED`, `OAH_FIX_PROXY_CREDENTIALS`, `OAH_FIX_BUSY`,
  `OAH_FIX_ATTEMPT_UNFINISHED`, `OAH_FIX_BIND_REQUIRED`, `OAH_FIX_HISTORY_INVALID`, `OAH_FIX_NOTHING_TO_FIX`,
  `OAH_FIX_NOT_REQUESTED`, `OAH_FIX_DIRTY_TREE`, `OAH_FIX_HEAD_UNRELATED`, `OAH_FIX_FINDING_UNKNOWN`,
  `OAH_FIX_NOTHING_TO_BIND`, `OAH_FIX_NOT_COMMITTED`, `OAH_FIX_MANIFEST_INVALID`, `OAH_FIX_TRAILER_MISSING`,
  `OAH_FIX_ENGINE_MISMATCH`, `OAH_FIX_NOTHING_TO_ABORT`. Usage 2 (`OAH_USAGE`). Environment 69
  (`OAH_FIX_GIT_FAILED`, storage, config, `OAH_REVIEW_RECORD_EXISTS` and `oah call`'s environment codes).
  Warnings: `OAH_FIX_OUT_OF_SCOPE`,
  `OAH_FIX_INTENT_CHANGED`, `OAH_FIX_RETURN_INVALID`, `OAH_FIX_UNQUOTABLE_PATH`.
- **Commit guidance** works in sh and PowerShell 5.1: one command per line, double-quoted messages with no
  `$`, backtick or `!`, `git add -u` for tracked changes and `git add -- <path>` for new files. A path outside
  `[A-Za-z0-9._/-]`, or one starting with `-` (Windows PowerShell 5.1 may drop `--` for native commands), is
  written `':(literal)<path>'`; a path with `'` or a non-printable character is listed for the user instead.
  Files that were untracked before the run are the user's, not part of the correction.

## Seam changes in landed code

- **`oah.call`** (AC3, Ctrl-C): `_run_prepared` waits for the worker in `POLL_SECONDS` slices instead of one
  blocking `communicate`, because Windows delivers Ctrl-C to Python only between waits. On any interruption from
  the moment the child exists (also inside the lease guard), it stops the worker's process tree (its own POSIX
  session or Windows job) and reaps it before re-raising; before this, a Ctrl-C left the worker running in its own
  session. `execute` records an interrupted run as `failed` with `OAH_RUN_INTERRUPTED` before re-raising, so a
  run folder never stays `running`. Timeouts, results and every other path are unchanged; the P3b and P6a tests
  stay green.
- **`oah.review.receipts`** (user guidance only): the unfinished and unbound attempt problems now end with the
  command that resolves them (`oah fix --abort --task T`, `oah fix --bind --task T`). Their existing words stay.
- **`oah.review.rounds`**: the "requested changes, but no finished correction attempt" wait names
  `oah fix --manual` for manual corrections. Counting, cache and decision rules are untouched.
- **`oah.runs`**: C6 adds the optional `worker_output` field for byte counts and digests only. The run folder
  gains `correction.json` and `correction.patch` through the public `Run.file_path` and `oah.atomic` writers,
  as `skills.json` already does.

## C1 correction decisions

- Interruption kills the owned process group or Windows job whenever a child was created, including after
  its launcher exited. The fake corrector can leave a descendant holding both output pipes; regressions
  interrupt only after the real launcher exited and verify the descendant stops writing. The Windows
  variant is guarded and requires a native Windows run.
- Every string in correction metadata and returned output is redacted before serialization. A changed
  filename containing a runtime credential fails the attempt and withholds the diff (including Git's encoded
  filenames) and all commit commands; sensitive generated or saved commands are withheld too. This avoids
  binding an applied attempt using redacted filenames.
  The user must rename or discard the affected files before retrying; there is no automatic recovery.
- Automatic and manual corrections compare the complete current binding and digest with the source
  receipt, then compare the committed intent sections at its reviewed head and current HEAD byte for byte.
  A mismatch refuses with `OAH_INTENT_SOURCE_MISMATCH` before preparation or attempt publication and asks
  for a review of the updated intent. Digest-equivalent newline changes also require that review; checkout
  newline conversion remains allowed because comparisons read committed blobs.

## C2 correction decisions

- One stop-signal scope starts before attempt publication and remains installed through inspection and
  durable terminal publication. Exceptions during inspection use the same aborted/failed settlement as
  dispatch exceptions. Record publication remains a signal-held atomic section; a signal during terminal
  publication is reported after that outcome is durable. Repeated stop signals cannot interrupt tree cleanup.
- `oah fix` opts into a private call cleanup scope that stops its owned process group or Windows job before
  returning, so descendants cannot keep changing files while the dispatcher inspects the result. Ordinary
  `oah call` and review calls retain their behavior and public signatures.
- Preexisting untracked files are snapshotted in memory (bytes, file kind and executable bits); symlink
  targets are read as link text. Modifications and deletions enter the displayed/saved patch, attempt evidence
  and scope accounting, with a separate `user_files` list in correction metadata. Unchanged user files stay
  absent from the patch. Binary changes get a binary-difference marker. C3 below supersedes snapshot-text
  redaction with raw-content scanning and withholding before diff construction.
- A run that changes user-owned untracked files fails and withholds all automatic commit guidance. The user
  must inspect and restore or keep those files before retrying; there is no automatic staging or recovery.
  This also prevents a corrector-staged user file from being swept into the suggested commit.

## C3 correction decisions

- Stop handlers are deferred across native process creation, assignment of the returned child reference,
  and Windows job assignment/resume. Pending signals run only after ownership is established, so cleanup
  stops the worker before the attempt is recorded as aborted. Default and ignored signal dispositions stay
  unchanged. Regressions inject SIGINT and POSIX SIGTERM before `Popen` returns; a guarded Windows SIGBREAK
  regression exercises the same boundary with a suspended child and its real job.
- Before any content diff is built, the credential scanner checks both raw sides of every changed file:
  committed blobs (including deleted files), current file bytes or symlink text, and preexisting untracked
  snapshots. A matching file is omitted entirely, identified only by its position, and forces `failed`
  without commit guidance. Git receives only explicit safe literal paths with rename detection disabled;
  safe changes remain reviewable. Post-diff redaction is defence in depth, never the content protection.
- Leftover-change diagnostics are best-effort, including repeated Git execution errors. Result diagnostics
  run before terminal publication, so an exception still settles the attempt as failed or aborted. The
  terminal record never depends on a successful diagnostic retry. Regressions cover repeated PermissionError
  after dispatch for failed and interrupted attempts, and failure while building the result.

## C4 correction decisions

- A changed submodule or gitlink is unsupported. Detection checks the starting tree, the current index and
  directory snapshots, including deleted, newly staged and untracked nested repositories. Change discovery
  forces `--ignore-submodules=none` so local ignore settings cannot hide them. Such an attempt fails,
  identifies affected entries only as `[file N]`, withholds the entire diff before construction and gives
  no commit guidance. Restore the unsupported changes before retrying; nested content is never expanded.
- Superseded by C5 below: every correction Git diff uses `--submodule=short`, `--no-ext-diff` and
  `--no-textconv`; external diff and textconv drivers cannot introduce unscanned bytes. These flags
  apply to both tracked diffs and the `--no-index` diffs for new files. Review behavior stays unchanged.
- `commit_commands` now requires the leased worktree root and prefixes every staging and commit command
  with `git -C '<directory>'`. Directory quotes work in sh and PowerShell 5.1, including spaces,
  metacharacters and apostrophes (concatenating a double-quoted apostrophe between single-quoted parts).
  Control characters in the directory refuse guidance and fail the attempt. Real-Git tests execute the
  commands from a subdirectory and another worktree with unrelated staged changes; a guarded Windows
  test repeats them in native PowerShell 5.1.

## C5 correction decisions

- G′ replaces Git-generated diff content entirely. Change discovery reads only tree/index metadata and
  compares raw working-tree snapshots; it never invokes a working-tree Git diff, including name-only
  diffs, because even those can execute clean/process filters. A prelaunch snapshot keeps untouched
  checkout conversions (CRLF, encoding and ident) from becoming correction changes. Nested directories
  are fingerprinted without following links or invoking Git's content conversion.
- Old sides come from `git cat-file blob <oid>` and new sides from raw working-tree bytes (or link text).
  Both are captured and scanned once, and `difflib` builds unified diffs from exactly that captured pair.
  No Git diff, filter, textconv, working-tree-encoding, EOL or ident conversion supplies patch bytes.
  Binary or invalid UTF-8 sides display byte counts only. Sensitive files, submodules/gitlinks and
  symlinks leaving the worktree are withheld by position and fail the attempt without commit guidance.
  Preexisting untracked snapshots use the same scan/capture/diff boundary. Post-diff redaction remains
  defence in depth; it is never the credential protection mechanism.

## C6 correction decisions

- Invariant I replaces corrector-output redaction with no text retention. Only `oah fix` opts into
  `CallRequest.retain_worker_text=False`; ordinary calls and reviews keep their landed behavior. Codex's
  `-o` file output is omitted and `--ephemeral` disables Codex session persistence, so its final message
  joins stdout. Both pipes stream live to stderr (keeping
  CLI JSON on stdout valid), with exact byte counts and SHA-256 digests in `result.json.worker_output`.
  No stdout/stderr log or last-message file is created, even on timeout or interruption. Stderr stays in
  memory for effort verification; unknown header labels never enter records. Correction returns
  remain visible in the terminal, without a saved final-message artifact or file-based return validation.
  A closed output terminal fails the stream and stops the owned process tree before the attempt is settled.
- Every correction cleanliness check, including preflight, bind and manual recording, compares tree and
  index modes/object ids plus raw working-tree bytes read by oah. No `git status`, content diff or content
  conversion is used. C9 below replaces the raw-mismatch refusal with unchanged checkout stat checks.
  `core.filemode=false`
  suppresses filesystem executable-bit differences, as needed on native Windows, without ignoring index modes.
- The baseline includes all index stages, modes and object ids. Any index-entry mutation fails the attempt
  before content inspection or diff construction. All affected paths are position-only, and the entire diff
  and commit guidance are withheld; staged blobs are never read. Interrupt diagnostics use the same rule.
- Correction and manual selection read receipts and the complete task round log under the task lock. They
  share the landed decision-stop settlement loop with review, excluding the missing-correction wait that
  `oah fix` itself resolves. An uncounted stop across any base refuses until an explicit decision settles it.

## C7 correction decisions

- The raw-input boundary also applies the landed `oah.toolkit.checks.CONTENT_RULES` key and env-secret
  patterns, alongside known runtime values. It scans both captured sides, including binary bytes and
  BOM-marked UTF-16, before constructing any diff. Matching files remain position-only and fail the attempt
  without commit guidance; unrelated privacy rules do not become correction-content refusals.
- Automatic binding requires a readable correction manifest with the matching attempt/start head, applied
  outcome, digest and string-list inventories/commands. Missing run folders, absent manifests and malformed
  metadata refuse with `OAH_FIX_MANIFEST_INVALID` before a head record is published. There is no automatic
  recovery or inferred empty inventory: restore the original run metadata and rerun binding. Manual attempts
  remain independent of run metadata, and abort still settles only unfinished attempts.

## C8 correction decisions

- Filenames use the same runtime-value and landed key/env-secret pattern scanner as raw file contents,
  before patch construction, metadata, evidence or commit guidance. This covers added, modified, deleted,
  renamed and preexisting untracked paths even when no matching credential is exported. Matching paths
  are identified only by `[file N]`, including failed/interrupted attempt diagnostics; completed inspection
  fails the attempt and withholds the diff and all commit guidance. Rename or discard those files before
  retrying; no automatic recovery is added. Dirty-tree refusals use the same position labels, and read
  errors for matching paths omit both the filename and the underlying exception text.
- The same scanner checks generated and saved executable guidance; binding never prints matching
  commands from an older correction manifest.

## C9 correction decisions

- `Prepared.retain_worker_text` is keyword-only so Orca's required subclass fields remain valid. Default
  text retention is omitted from serialized launches to preserve the landed Orca schema; an explicit
  `False` still round-trips for corrections. No launcher implementation or review behavior changes.
- Cleanliness accepts exact raw blob bytes or unchanged checkout stats read by `git ls-files --debug -z`,
  while still comparing tree/index modes, object ids and stages. Stat checks compare size, timestamps
  and, on POSIX, cached device/inode/owner identity. Zero nanoseconds use second resolution, including
  Git for Windows. A timestamp at or after the index timestamp is racy and requires content equality;
  an exact raw CRLF rendering of an LF blob also passes when those checkout stats match. No filters,
  status or Git content diffs run. Gitlinks still require the recorded HEAD and a clean nested tree;
  postlaunch directory snapshots continue to catch nested content and HEAD changes.
- Credential matching checks both raw sides with CRLF folded to LF for matching only, including
  normalized runtime credential values. Captured bytes and patches retain their original line endings.
- Commit guidance uses the platform shell's exact single-quote escaping for the leased directory:
  doubled apostrophes on PowerShell and concatenated quoted apostrophes on sh. Native Windows tests
  execute guidance in PowerShell from a subdirectory and another worktree.
- The filename env-assignment fixture assembles its variable name at runtime; a source-scanner regression
  prevents literal env-secret assignments from returning. The repository scanner reads HEAD and history,
  so the existing unpushed hit remains until the coordinator folds this correction into that commit.

## C10 correction decisions

- Retained-text calls use one uninterrupted `communicate(input=...)` in a communication thread; the
  dispatcher polls that thread in `POLL_SECONDS` slices. Stdin delivery and EOF continue independently
  of polling, including prompts larger than pipe capacity and readers delayed beyond the first poll.
  Timeout and interruption stop the owned process tree and join that same communication thread before
  returning; cleanup never starts a competing `communicate`. Correction streaming stays unchanged.
- Non-current bound-intent preflight refusals and post-correction warnings use the landed binding-state
  enum and fixed oah-authored guidance only. They omit parser explanations and packet-derived
  binding/source text, rather than relying on credential redaction. The same diagnostics serve text and
  JSON. Unexported credential-shaped Status values still cause raw-content withholding, a failed
  outcome and no commit guidance; non-credential intent changes retain their existing warning behavior.

## C11 correction decisions

- Correction exception diagnostics use one literal allowlist of codes and fixed next-step sentences.
  The core boundary, text/JSON CLI boundary and attempt/run error records never format exception text,
  filenames or arbitrary exception codes; unknown errors use a fixed fallback. Preparation, dispatch-lease
  and launch errors opt into this policy only for calls without retained worker text, preserving ordinary
  call and review behavior. Exception settlement writes the fixed diagnostic directly without optional
  leftover-change inspection. Packet field values and unexported credentials cannot enter diagnostics.
- The conversion-free index baseline uses `git ls-files --stage -v -z`: each entry includes its mode,
  object ID, stage and tag (lowercase for assume-unchanged, `S`/`s` for skip-worktree). Any tag change
  triggers the existing position-only `OAH_FIX_INDEX_CHANGED` failure before content inspection,
  with no diff or commit guidance. No index refresh or automatic flag repair is performed.

## C12 correction decisions

- Correction warnings use a fixed message catalog with counts, file positions and binding-state enums;
  they never interpolate lease scope, task metadata or filenames. Credential-bearing lease and packet
  scope metadata refuses with `OAH_FIX_SENSITIVE_SCOPE` before brief/run retention or dispatch. Correction's
  committed-packet reader checks the exact packet scope with the dispatcher's original credential scanner,
  before worker environment filtering; ordinary calls and reviews keep their landed behavior.
  Runtime-marker regressions scan both text and JSON across correction,
  failed/no-change, bind, manual, abort and refusal scenarios, including unexported scope credentials.
- Review and correction decision gates share the same wait-reason function and task-log settlement loop,
  including ancestry ambiguities after amended or rewritten bound corrections. Correction excludes only
  the missing-correction wait it resolves. Both automatic and manual correction refuse before dispatch or
  publication until the existing review decision mechanism settles the stop; no recovery state is added.

## Review Focus

1. **Stopping `oah fix` mid-run** (Ctrl-C, SIGTERM, a closed terminal, a hard kill). Expect the corrector's
   process tree stopped and exactly one `aborted` outcome; after a hard kill, an unfinished attempt that every
   later `oah fix` and `oah review` refuses until `oah fix --abort`. → Task 2 `test_interrupt_stops_the_tree`,
   Task 3 `test_interrupted_correction_stops_the_corrector_and_records_aborted`, Task 5
   `test_cli_sigint_records_aborted`, `test_cli_sigterm_records_aborted`, `test_cli_killed_fix_needs_abort`.
2. **A Codex correction committed with the lead's own trailer** (a false `independent: true` on the next
   review). Expect `OAH_FIX_ENGINE_MISMATCH`; `--engine` overrides only when the commits really replace
   Codex's changes, and that is recorded. → Task 4 `test_bind_refuses_until_committed_cleanly_with_trailers`.
3. **A corrector that commits or edits outside the scope or the intent.** Expect a failed attempt when HEAD
   moves, and warnings for out-of-scope paths and a changed intent source. → Task 3
   `test_a_corrector_that_commits_fails_the_attempt`, `test_out_of_scope_and_intent_changes_warn`.
4. **The correction brief's intent section drifting from the review brief's** (CRLF packet, `core.autocrlf`).
   Expect identical bytes. → Task 3 `test_brief_carries_the_findings_and_the_review_section`.
5. **Credentials reaching the corrector or anything retained or printed.** → Task 6
   `test_corrector_environment_excludes_credentials`, `test_runtime_credentials_never_reach_records_or_output`.
6. **An agent looping on `oah fix`** (paid calls). Expect `OAH_FIX_NOTHING_TO_FIX` once every P0/P1 finding has
   an applied attempt, and `OAH_FIX_WORKER_REFUSED` inside a worker. → Task 3
   `test_fix_refuses_unknown_or_already_corrected_findings`, Task 3 `test_correction_runs_as_a_worker_in_the_leased_worktree`.
