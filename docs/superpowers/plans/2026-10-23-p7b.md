# P7b Guided `oah init` and the SessionStart Hook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oah init` is the one guided setup of PLAN 6.5 and section 7. It checks tools and installs only
the confirmed ones, walks through the Claude Code and Codex sign-ins, prints its whole plan, then creates
the project environment with the owner's defaults and builds the first impact map. A second run changes
nothing except refreshing a stale map. `oah hook session-start` prints nothing for a dispatched worker.

**Architecture:**
- **`src/oah/init.py`** is the core. It plans every file, managed block, hook, unlazy install, CI starter,
  companion step and map build as data, then applies a plan. Settings are parameters; every machine
  collaborator (`which`, install runner, sign-in status runner, companion runner and probe, `ask`, PATH
  refresh, env, home, OS, today, unlazy source and pin) sits in one `Machine`, so tests run against fakes.
- **`src/oah/init_cli.py`** is the command: arguments, answers, printing the plan, the final confirmation,
  the apply order and exit codes. Tests reach it through real command discovery (`oah.cli.main`), with
  `init_cli.make_machine` patched to return a fake `Machine`.
- **`src/oah/hook_session_start.py`** is `oah hook session-start`, dispatched by the landed `hook_cli`.
- **`src/oah/templates/init/`** holds the config, tier agent, `.graphifyignore`, `.gitignore` and
  `.oah/templates/README.md` templates.
- Landed code does the work, unchanged: `oah.setup.guide` (tools, installs, sign-ins), `oah.setup.companions`
  (Orca, Aside, the Aside rules text), `oah.rules` (AGENTS.md block, CLAUDE.md import), `oah.wiki`
  (scaffold files, index lines, the wiki lock), `oah.impact.mapstore` (status, build, refresh), `oah.unlazy`
  (pin, install commands, verification), `oah.hooks` (diffs, install), `oah.ci` (plan, write), `oah.models`
  (tier model mapping), `oah.intent.FOOTER`.

**Tech Stack:** Python 3.11+ stdlib (`argparse`, `tomllib`, `difflib`, `dataclasses`, `unittest`), git through
`oah.paths` and `oah.engines.proc`.

**Spec:** `docs/PLAN.md` 3, 5.1, 5.3, 5.5, 5.8, 5.11, 5.12, 6.5, 7, 8, A6, A8d, A9–A12, A14, A15, A17, A20, A21,
and the P7/P7b items of section 15. The lane intent `p7b` r1 in the dispatch brief is authoritative.

## Global Constraints

- Everything from the earlier plans still applies: stdlib only, never `shell=True`, UTF-8 on every read
  and write, parsers accept CRLF, writers keep a file's line endings, a Korean one-line header on new `.py`
  files, executables resolved through `oah.engines.proc` (never a `.cmd`/`.bat` launched directly), test
  writes inside the checkout, no network in tests.
- **Plan first.** Nothing is written, installed or run (beyond read-only lookups: `which`, read-only git,
  `mapstore.status`, `hooks.install(dry_run=True)`, `ci.plan`) before the full plan is printed. The plan is
  one pure rendering of one `Plan` value, so `--dry-run` prints exactly what a real run prints. A dry run
  asks nothing, runs no sign-in status command and creates nothing, not even the state folder.
- **Never overwrite.** An existing file is kept unless `--force`. Managed content changes in place:
  the AGENTS.md block and the CLAUDE.md import line through `rules.sync`, missing `.gitignore` entries,
  the index line of a guide note init creates. `--force` replaces init's own files when they differ
  (config, `.oah/templates/`, wiki templates and guide, `.obsidian/*.json`, tier agents, `.graphifyignore`,
  the CI starter after its diff, foreign git hooks with backup, an incompatible project unlazy copy moved
  aside), and never the wiki's `index.md`, `log.md` or archives. A file that changed between the plan and
  the write is skipped with `OAH_INIT_CHANGED`.
- **Questions** (each `--with-<x>` / `--without-<x>`): `agents`, `hooks`, `unlazy`, `graph`, `ci`, `orca`,
  `aside`, `jev`, `skill-updates`. Enter takes the default: yes for agents, hooks, unlazy and skill updates;
  no for graph, CI (private-repository minutes can cost money), Orca and Aside. `jev` has no default: it
  needs a typed `y` or `n`, is marked "yes (recommended)", states the cost and the data sent, and records
  the answer and its date in `[rerank]`. `jev` and `skill-updates` are recorded in `.oah/config.toml`, so
  they are asked only when init writes that file; an existing config answers them. A key alone never
  enables Jev, and init never calls `oah.secrets`.
- **Interactive** means stdin is a terminal. A non-interactive real run with any question unanswered refuses
  with `OAH_INIT_ANSWERS_REQUIRED` (exit 2), lists the missing flags, and writes nothing. It never reads
  stdin. A dry run labels unanswered questions with their default (Jev: off) instead. End of input during a
  question refuses with `OAH_INIT_NO_ANSWER` (exit 1). An interactive run with changes asks
  `Apply this plan? [Y/n]` once after the plan; `n` ends with `OAH_INIT_DECLINED` (exit 1).
- **`--yes` confirms tool installs only.** Companion setup commands, including all user-level configuration
  changes, still require a separate explicit answer for each step. It answers no other question.
- **Apply order:** tool installs → sign-ins → files → managed blocks (deferred when Aside is selected) →
  hooks → CI starter → unlazy → companion apps → the preplanned rules alternative when Aside is selected →
  effective ignore verification → impact map. A failed step is reported with its retry command and the
  rest continues; no publication is replanned or retried after a concurrent-change refusal.
- **Impact map last.** `mapstore.ensure_fresh` after every write. Any failure prints
  `OAH_INIT_IMPACT_UNAVAILABLE: <reason>; retry with oah impact build`, reports `impact=unavailable`, and
  does not fail init. It is never labelled fresh.
- **Exit codes and last lines:** 0 with `OAH_INIT_DRY_RUN changes=<n> impact=<build|refresh|fresh|unavailable>`,
  `OAH_INIT_UNCHANGED impact=fresh` or `OAH_INIT_DONE changed=<n> impact=<built|refreshed|fresh|unavailable>`;
  1 with `OAH_INIT_INCOMPLETE changed=<n> impact=<…> pending=<names>` when a required tool is missing or
  signed out, or a requested step failed or is pending; 1 refused (`OAH_INIT_DECLINED`, `OAH_INIT_NO_ANSWER`,
  `OAH_RULES_*`); 2 usage (`OAH_INIT_ANSWERS_REQUIRED`, argparse); 69 environment (not a repository, git
  missing, invalid existing config, storage, wiki recovery pending).
- **A17.** oah never reads, stores or asks for a password, key or token. Sign-in is verified only by each
  tool's own status command through `guide.walk_sign_ins`, whose output is never printed. Templates name
  `${TYPESAFE_API_KEY}` only. `.gitignore` gains `.env`, `.env.*`, `*.pem`, `*.key`, `.oah/secrets*` and
  Claude Code's local settings `.claude/settings.local.json` and `.claude/settings.local.json.oah.bak`
  (local MCP approvals and oah's local hooks, including the installer's preserved backup).
- **SessionStart hook:** with `OAH_WORKER=1` it prints nothing and exits 0 before touching the repository.
  Otherwise it prints at most about ten short lines (the rules location, active leases, the newest wiki log
  entries, how to start a task) and always exits 0, printing nothing outside a repository or on any error.

## Review Focus

1. **Existing user files with CRLF and no final newline** (AGENTS.md, CLAUDE.md, .gitignore, index.md): every
   byte is kept and only the block, the import line or missing entries are added in the file's line ending.
   → Task 2 `test_gitignore_adds_only_missing_entries_in_file_line_ending`, Task 5
   `test_existing_files_keep_user_content`.
2. **No terminal, no flags** (CI, a pipe): refuse before any write or install and never read stdin.
   → Task 4 `test_noninteractive_refusal_lists_missing_flags`, Task 5 `test_noninteractive_without_flags_refuses`.
3. **A Jev key in the environment without consent:** Jev stays off and init never looks the key up.
   → Task 4 `test_jev_question_requires_typed_answer`, Task 5 `test_key_alone_never_enables_jev`.
4. **A fresh `git init` with no commit:** the map is `unavailable` with the retry command, everything else is
   created and init exits 0; after the first commit a second run only builds the map.
   → Task 5 `test_no_commit_repository_marks_map_unavailable`.
5. **Run from a subdirectory or a linked worktree:** files land at that worktree's root, the map is that
   worktree's. → Task 5 `test_init_from_subdirectory_writes_at_worktree_root`.

## C1 correction decisions

- **Hook plan privacy (finding 1):** Claude hook diffs show only the canonical hook addition, labelled as
  such. No existing settings, environment entries, matchers or foreign command text enters the plan.
  The landed installer still preserves existing settings; init discards its settings diff.
- **Private backups (finding 2):** ignore both local settings and their exact `.oah.bak` backup before
  invoking the landed installer. Refuse if either path is tracked or linked, or if either effective ignore
  rule is missing at apply time (including a later negation). Init never unstages user content automatically.
- **Companion consent (finding 3):** never forward init's `--yes` to companion setup. Each command retains
  the landed explicit confirmation; without a terminal it stays pending. App selection and the overall
  plan confirmation do not authorize user-level MCP registration or other global configuration writes.
- **Create publication (finding 4):** check links again at apply time. POSIX creates walk parents with
  `O_NOFOLLOW` directory descriptors and publish with descriptor-relative exclusive hard links; redirected
  pathnames cannot change the publication directory. Windows holds handles to every parent, rejects reparse
  directories, and denies write/delete sharing until the landed exclusive publication completes. Wiki
  creation retains the landed wiki lock. Changed or unsafe paths are skipped with `OAH_INIT_CHANGED`.
- **unlazy paths (finding 5):** reject linked project skill candidates before discovery can resolve them.
  Only the two lexical project copy locations may be replaced. Revalidate install, staging, replacement
  and backup paths immediately before mkdir, clone commands and renames; cleanup never traverses a link.
- **Git hook locality (finding 6):** allow project-local destinations and the repository's own common
  hooks directory (including linked worktrees), with no linked path components. Refuse shared external
  `core.hooksPath` destinations. Recheck locality and the planned destination at installation time.
- **Orca idempotence (finding 7):** adapt the landed companion steps in init only. Compare the bundled
  guide names (`orca skills list --json`) with `orca skills installed --json`; check project setups using
  `orca project setups --project <id> --host local --json`, requiring the requested project, local host,
  exact folder and ready state. Skip satisfied steps. Unsupported, malformed, unavailable or conflicting
  status stays pending, with no automatic recovery or persisted completion flag. Probe output is discarded;
  no probe runs during planning or dry-run. Missing steps still require explicit per-command consent.
- **Installer disclosure (finding 8):** render every companion command display line and its source in the
  initial plan, including the full Windows Aside download/signature-check script. Tool installation consent
  cannot truncate or bypass this disclosure.

## C2 correction decisions

- **Git hook plan privacy (finding 1, owner J):** discard the landed Git hook diff as well as the Claude
  settings diff. Show canonical additions only; describe an existing target with `replaces N bytes
  (sha256 <digest>)`. CI replacement previews follow the same rule. Existing bytes are retained only in
  memory for preservation and change detection, and in the explicitly required local hook backups;
  they never enter plan output, diagnostics, logs or runtime state. CLI errors retain fixed error codes
  and recovery instructions without echoing private configuration keys or invalid user-file contents.
- **External diagnostics (finding 2, owner J):** discard clone/check-out stdout and stderr, reporting only
  the Git operation, exit code and timeout flag with a retry instruction. Init adapts installer and companion
  execution to capture and discard external output rather than inheriting the terminal. Pin/map failures
  use fixed explanations instead of forwarding raw diagnostics from landed modules. Sign-in verification
  continues through each tool's own status command, with no credential lookup.
- **One publication path (finding 3, owner K):** `_publish` handles file creates, updates, replacements,
  hook backups and installations, rules, Aside rules, the CI starter, and unlazy directory moves. POSIX
  retains no-follow parent descriptors and publishes relative to them; Windows retains non-reparse parent
  handles denying write/delete sharing. After staging and flushing bytes, recheck the target's planned
  digest immediately before atomic publication. A changed target, parent or linked component refuses with
  `OAH_INIT_CHANGED`. Directory moves recheck the planned tree digest and use exclusive atomic renames.
  Landed modules still generate/validate content and own wiki locking and external runtime state; init
  adapts their publication instead of calling their separate writers. There is no automatic rollback:
  unlazy clones and verifies before moving the old copy, and a conflict after that backup move leaves the
  backup for explicit recovery. Clone staging is isolated at the worktree root from mutable skill parents.
- **Destination boundary (findings 3–4, owner K):** apply one cross-platform path grammar before planning
  configured wiki paths and before every publication. Reject roots, drives (including drive-relative paths),
  traversal, Windows device/stream aliases, and linked/junction components. Normalize accepted separators.
  C2 supersedes C1's common-hook-directory exception: every init publication must remain within the current
  worktree. Linked worktrees whose shared Git hook directory lies outside it must select a project-local
  `core.hooksPath`; init refuses rather than changing Git configuration automatically.

## C3 correction decisions

- **Conditional Aside publications (finding 1, owner K):** plan both rules alternatives and the local
  rules addition before confirmation, retaining the original target bytes for every destination. When
  Aside is selected, defer the single AGENTS.md/CLAUDE.md publication until registration is checked,
  then choose the already planned alternative. Apply never replans rules or takes a new local baseline;
  a changed target refuses with `OAH_INIT_CHANGED` and leaves init incomplete, with no later retry on
  that file. Keep the public standalone `add_aside_rules` helper as a plan/publish wrapper.
- **CI command privacy (finding 2, owner J/A17):** guided init does not forward `[ci].test_command` from
  an existing config. The landed CI planner uses its own detected command or its fixed failing
  "Run tests (edit me)" placeholder. The original config stays intact; its command never enters the
  displayed plan, generated workflow or runtime state. Explicit `oah ci init` behavior is unchanged.
- **Effective ignore protection (finding 3):** appending missing text is only scaffolding. Before
  reporting success, run `git check-ignore --no-index -q` on representatives of every required pattern,
  including existing matching names, wildcard parent directories and nested ignore locations. This
  uses Git's actual negation/precedence rules without filters or reading secret-file contents. An
  unprotected path reports its fixed required pattern and leaves `gitignore` pending with
