# Task budget — correction C4

## Problem

Structured review missed limits added after an unlimited run, and managed dispatch skipped later
budget checks. Round-log validation accepted malformed stop fields and could echo their contents or
allow decision overrides. Task limits and stops must cover every paid path and survive restarts.

## Decision

Use `rounds.resolve_task_budget` for the strictest limit from every saved limit, the live worktree,
the current default merge-base, every recorded review base and the explicit review base, together
with the validated task stop. Persist newly observed limits as `limit`
events under the task and state locks, including on budget refusal. These events spend no round and
do not invalidate cached approvals. When no source configures a limit, the task remains unlimited.

Calls, fixes and structured reviews use this resolver before paid preparation and engine launch.
Managed review carries its live worktree/base into snapshot dispatch, rechecks instead of bypassing
the gate, and reconciles its own start reservation by run ID. A recorded `--extra-round` authorizes
only that run; later calls still face the task limit. Reviewer policy remains pinned to the base;
only the task budget also reads live configuration. Correction checks reuse captured history while
validating the live stop log between publications. After publication starts they consume the exact
validated bytes, preserving correction's compare-before-write boundary.
Limit appends compare the original captured bytes, and correction scans stop text before any owned
append. If corruption is found after the attempt start, preserve the corruption refusal and leave
that start for settlement after the user repairs the log.

`read_round_log` uses one closed event schema: start, finish, reservation, dispatch and limit. It
checks required fields and all optional fields, including message strings, receipt identifiers,
heads, outcomes, timestamps, decisions, numbers and task identity. Landed start/finish events may
omit legacy optional fields (including task); any supplied task must match. Counted finishes require
a receipt identifier. Unknown fields/events and malformed values refuse with
`OAH_REVIEW_STATE_INVALID`, preserve the bytes and cannot be overridden. Stop diagnostics identify
only the OAH code, event position and digest; saved message text is never interpolated.

User-visible changes, one per finding:

1. A limit added after unlimited reviews also stops the next structured review.
2. Malformed stop message or receipt fields refuse before a decision can authorize continuation.
3. Lowered limits reach call, fix and review together and remain saved after configuration removes them.
4. Corrupted round logs stop every path until repaired from trusted history; diagnostics do not echo them.

## Correction C5

A schema-valid start without a receipt is a pending round and invalidates an older approval.
The two failing fixtures instead use `run_id="later"`, which C4 correctly rejects. Keep that strict
validation. Catch `ReviewError` at landing's shared `_review_check` boundary and return the existing
`OAH_LAND_REVIEW_REQUIRED` refusal without copying exception text or stored values. Assessment and
post-confirmation revalidation use this same boundary; neither repairs or rewrites review state.

1. Users now get `OAH_LAND_REVIEW_REQUIRED` and guidance to inspect review history instead of an assessment crash.
2. Review changes during confirmation now give that same refusal and a landing record instead of `OAH_LAND_FAILED`.

## Correction C6

Resolve the current default merge-base independently of the selected series, and collect bases from
all task receipts and start/finish log entries. Every existing paid preparation and launch recheck
uses this same resolver under task/state locks; save each newly observed limit once, including on
budget refusal. Missing historical commits or unreadable configurations refuse with a safe OAH
diagnostic. Decision stops, C4 validation, C5 landing behavior, cached approvals and the scope of
`--extra-round` are unchanged.

1. A limit at a new default merge-base now stops calls, fixes and reviews, including queued foreground/background launches.
2. A lower limit in any task-visible budget source now applies everywhere and remains recorded; `--extra-round` permits exactly one additional round.
