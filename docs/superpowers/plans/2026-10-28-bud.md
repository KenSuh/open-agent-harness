# Task budget — correction C3

## Problem

Task stops and optional review limits must cover every paid dispatch path and survive restarts.
Failed reviews lost spend, ordinary dispatches broke approval caching, fixes forgot newly configured
limits, and optional paid preparation ran outside the task's authorization boundary.

## Decision

Keep no ceiling as the default and retain `max_rounds` as a budget for review runs, shared across bases.
Initial and correction calls must pass the same task stop/limit gate. Do not add time or usage budgets.

1. Reserve a structured review before preparation using its eventual run ID. Count every start,
   including failed/interrupted starts, and reconcile a published receipt by that ID. A receipt's
   `counted` flag still describes validated output; it does not erase reserved spend.
2. Use the approving receipt's matching start/finish as the publication boundary under the task lock.
   Ordinary activity preceding it cannot invalidate the approval; later activity must invalidate it.
   This also handles legacy dispatch log entries without round numbers and publication without a finish.
3. Include the effective fix limit in the scanned, immutable correction plan. Persist its dispatch
   entry inside the existing checked start publication, before creating the run or starting Codex.
   Advance the captured log bytes after this owned append so terminal publication still detects changes.
4. Hold the task lock throughout ordinary preparation, including difficulty advice, skill ranking and
   model choice. Reserve before those requests under the lease/state lock, then release the state lock
   during preparation. The eventual foreground/background/queued launch uses the same run reservation,
   rechecks current stops/limits, and retains the existing replay refusal. Managed review/fix paths
   already hold the task lock. Failed preparation retains its reservation conservatively.

User-visible changes, one per finding:

1. A failed or interrupted review spends its reserved round; at the limit, retry needs `--extra-round`.
2. Repeating an approved review returns the cached approval even after earlier initial/correction calls.
3. A limit that governed a fix stays enforced when later configuration omits it.
4. A competing preparation refuses before paid advice; preparation and engine launch spend one slot.
