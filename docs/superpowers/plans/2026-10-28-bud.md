# bud C1 — task review budget

## Problem

Review stops and max_rounds guarded only structured reviews. Other paid calls could bypass them,
and changing the review base reset the limit's count. Saved round logs lacked semantic validation.

## Decision

- One task gate checks explicit decision stops, invalid history and max_rounds before paid dispatch.
  Review keeps its additional missing-correction and attempt checks; corrections can resolve missing
  corrections, but cannot bypass an explicit stop or an exhausted limit. A cached approval costs nothing.
- Count structured review receipts across all bases. Preserve ordinary review-stage calls of every kind
  and tier by counting their dispatch reservations in rounds.jsonl. Reserve immediately before spawning,
  under the task and state locks; a failed/interrupted spawn retains that reservation conservatively.
  Structured reviews keep their existing completed-receipt accounting, without double counting.
- Save max_rounds in the same append-only log. The strictest recorded/current limit applies task-wide,
  so changing base or omitting a setting cannot silently clear it. No limit stays the default when none
  was configured. Use oah review --extra-round for one recorded override; use --decision to settle a stop.
- Recheck prepared and background handoffs at the actual engine start. Managed review/fix owns the same
  task lock and applies its checked overrides. Ordinary saved launches cannot be replayed after dispatch.
- Validate stop/count/limit fields and task identity before reading their meaning. Accept older valid logs
  without task identity fields; reject existing empty, malformed, foreign and wrong-type state with a fixed diagnostic,
  preserving original bytes and avoiding reflection of untrusted state in errors. Never reset spend.

## User-visible differences

1. Stopped or exhausted tasks refuse call (every stage, including background), fix and review before an engine starts.
2. Changing base no longer resets the limit; ordinary review-stage calls also spend the task's round budget.
3. Invalid saved budget/stop state refuses with repair guidance instead of silently continuing.
