# fx2 `oah finish` After `oah wiki maintain` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oah finish` works after a real `oah wiki maintain --task T`. It exempts the recorded
maintenance outputs from the scope check and records them in the finish event, instead of stopping
with `AttributeError: 'MaintenanceCheck' object has no attribute 'outputs'`.

**Architecture:**
- **One source of truth.** `MaintenanceCheck.outputs` becomes a read-only property over
  `record["outputs"]`, the dict `oah wiki maintain` writes. It returns `(path, digest)` pairs sorted
  by path, or `None` when there is no record or the dict is not `str → 64 lowercase hex`.
- **Verifier.** `Wiki.verify_task` reads the outputs only through that property. A malformed dict is
  an `OAH_WIKI_MAINTENANCE_STALE` problem, so `ok` is False.
- **Finish.** `_wiki_maintenance` in `lease_cli.py` iterates `check.outputs`. When `ok` is True but
  `outputs` is `None`, it refuses with the existing `OAH_WIKI_MAINTENANCE_MISSING`, or records the
  override under `--allow-missing-wiki-maintenance`. It never raises another exception.

**Tech Stack:** Python 3.11+ stdlib, `unittest`, real `git` and `python -m oah` subprocesses.

**Spec:** `docs/PLAN.md` 5.4 (finish), 5.10 (wiki maintenance, A8), A12; intent fx2 r1.

## Correction C1 — Finding 1

- Validate all output entries before sorting and reject NUL-containing paths in `MaintenanceCheck.outputs`.
  This keeps one validation boundary: mixed keys and NUL paths return `None`, so `verify_task` uses the
  existing malformed-output stale refusal without reading those paths or echoing their contents.
- User-visible change: malformed outputs refuse by name instead of crashing; the recorded override works
  and grants no wiki scope exemptions.
- Regression coverage: mixed string/integer keys and NUL paths in the property; a byte-exact JSON-escaped
  NUL in a real maintenance record, checked through the verifier and real finish subprocesses with and
  without the override. The override still requires scope for wiki edits.

## Correction C2 — Findings 1 and 2

- Finding 1: reject lone-surrogate paths at `MaintenanceCheck.outputs` before path construction or reads,
  using the allow-list below rather than adding another deny check or catching encoding exceptions.
  User-visible change: a JSON-escaped lone surrogate yields the named stale-maintenance problem instead
  of a traceback, both with and without the maintenance override.
- Finding 2: accept only plain `str` paths fully matching `WIKI_MAINTENANCE_OUTPUTS`, shared by the
  property and the finish exemption check. Keep the existing pattern and digest validation, validate
  every entry before sorting, and reject the whole outputs mapping if any entry is invalid.
  User-visible change: malformed or unsupported paths produce the existing stale-maintenance problem;
  the recorded override still grants no scope exemptions, so wiki edits require scope.
- Regression coverage added before the fix: byte-exact JSON-escaped lone-surrogate records and a
  table of NUL, surrogate, absolute, parent, backslash, other unsupported and non-string/mixed keys.
  Property tests also reject `str` subclasses and distinguish full matches from suffixes and newlines.
  Real verifier and finish subprocesses test both override modes without touching malformed paths.
  Windows drive and UNC spellings are covered portably; no native Windows filesystem run is claimed.
