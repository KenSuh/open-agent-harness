# fx2 `oah finish` After `oah wiki maintain` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oah finish` works after a real `oah wiki maintain --task T`. It exempts the recorded
maintenance outputs from the scope check and records them in the finish event, instead of stopping
with `AttributeError: 'MaintenanceCheck' object has no attribute 'outputs'`.

**Architecture:**
- **One source of truth.** `MaintenanceCheck.outputs` becomes a read-only property over
  `record["outputs"]`, the dict `oah wiki maintain` writes. It returns `(path, digest)` pairs sorted
  by path, or `None` when there is no record or the dict is not `str → 64 lowercase hex`.
- **Verifier.** `Wiki.verify_task` reads the outputs only through that property. A malformed dict is
  an `OAH_WIKI_MAINTENANCE_STALE` problem, so `ok` is False.
- **Finish.** `_wiki_maintenance` in `lease_cli.py` iterates `check.outputs`. When `ok` is True but
  `outputs` is `None`, it refuses with the existing `OAH_WIKI_MAINTENANCE_MISSING`, or records the
  override under `--allow-missing-wiki-maintenance`. It never raises another exception.

**Tech Stack:** Python 3.11+ stdlib, `unittest`, real `git` and `python -m oah` subprocesses.

**Spec:** `docs/PLAN.md` 5.4 (finish), 5.10 (wiki maintenance, A8), A12; intent fx2 r1.

## Review Focus

- `outputs` is the only reader of `record["outputs"]`; there is no second copy that can drift.
- A tampered `maintenance.jsonl` (outputs a list, a non-hex digest, a non-string key) gives a named
  refusal, never a traceback.
- The finish-guard tests build the real `MaintenanceCheck`, so a renamed field breaks them.
